# How static-analysis tools parse, resolve and model Python: guidelines for Mental's `extract` crate

Evidence is the source code of each project at the commit given. All clones were shallow and read-only; nothing was built or run from inside them. Two local measurements (dependency counts, API churn) were made with `cargo tree` and `git diff` from a scratch directory outside the clones; they are marked "local measurement".

- **ruff** (`astral-sh/ruff` @ `b140af2f`, 2026-11-13): Rust linter and formatter. Hand-written, error-recovering Python parser producing a typed AST, plus a binding/scope model that the linter fills during its own AST walk. Its crates are now on crates.io as unstable `0.0.x` versions.
- **ty** (inside the ruff repo): Astral's type checker. Its 236k-line semantic crate on salsa is the real cross-module resolver. Too large for Mental. Its Markdown "mdtest" test format is worth knowing.
- **tree-sitter-python** (`tree-sitter/tree-sitter-python` @ `26855eab`, 2025-09-15): grammar for an incremental, error-tolerant C parser that produces an untyped concrete syntax tree (CST), with Rust bindings.
- **stack-graphs / tree-sitter-graph** (`github/stack-graphs` @ `fcb7705d`, 2025-09-09, archived; `tree-sitter/tree-sitter-graph` @ `b930fb59`): name resolution written as a graph-building DSL over tree-sitter. The design is elegant, but the project is dead and heavy. Its caret-assertion test format is the best thing to take from it.
- **PyCG** (`vitsalis/PyCG` @ `8d5dc408`, 2023-11-26, archived): Python call-graph generator. Its main value is the micro-benchmark suite: 18 categories of `main.py` + `callgraph.json`.
- **CodeQL Python** (`github/codeql` @ `20ed6480`, 2026-11-13): framework models written in QL over "API graphs", "models-as-data" YAML rows with an access-path grammar, a Python control-flow extractor, and inline-expectation tests.
- **scip-python** (`sourcegraph/scip-python` @ `51dd05f5`, 2026-11-11): a Pyright fork that emits SCIP indexes. It runs on Node and needs a pip environment. Looked at only briefly.

## Which parser and resolver give the most compact correct Python implementation in Rust today?

### Takeaway
Parse with `ruff_python_parser` + `ruff_python_ast`, pinned to an exact version, and write Mental's own small resolver. Copy ruff's ideas (the `ReadResult` outcome enum, qualified-name resolution, typing a binding from its initializer) rather than depending on `ruff_python_semantic`. That crate is only half a resolver: the linter's 4,000-line visitor fills it. Do not use tree-sitter, stack-graphs, SCIP or ty for version one. The cost of this choice is an unstable API on a weekly release cadence, so ruff types must stay inside `extract`.

**ruff parser: API and error recovery**
- Entry points are `parse_module(source) -> Result<Parsed<ModModule>, ParseError>` (line 112) and `parse_unchecked(source, options) -> Parsed<Mod>` (line 289). `Parsed<T>` (line 395) holds `syntax()`, `tokens()` and `errors()`. `parse_unchecked` always returns an AST and lists the syntax errors beside it, so the parser recovers from errors — [crates/ruff_python_parser/src/lib.rs#L112-L470](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_parser/src/lib.rs#L112)
- It is a hand-written recursive descent parser with Pratt parsing for expressions — [crates/ruff_python_parser/README.md](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_parser/README.md)
- The AST is typed and generated from `ast.toml` (81 node sections). For example, `StmtTry { node_index, range, body, handlers, orelse, finalbody, is_star }` has named fields that mirror CPython's `ast` module. Every node carries a `TextRange` and an `AtomicNodeIndex` — [crates/ruff_python_ast/src/generated.rs#L9465](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_ast/src/generated.rs#L9465), [crates/ruff_python_ast/src/node_index.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_ast/src/node_index.rs)
- A ready-made `Visitor` trait with `walk_stmt`/`walk_expr`, plus a source-order visitor, ships in `ruff_python_ast` — [crates/ruff_python_ast/src/visitor.rs#L135](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_ast/src/visitor.rs#L135)
- Size: parser about 21k lines of Rust, AST about 29k lines, semantic crate about 6.4k lines — local measurement (`wc -l` on the clone).
- **Dependency cost, local measurement** (`cargo tree -e normal,build`, distinct crates): parser + AST + text_size + source_file = **62 crates**, including two `syn` majors, phf codegen and proc-macro helpers. Adding `ruff_python_semantic` brings it to **76 crates** (adds `ruff_cache`, `ruff_macros`, `regex`, `globset`). `tree-sitter` 0.25 + `tree-sitter-python` 0.25 = **21 crates**, plus a C compiler through `cc`. Compile time was not measured, because building was out of scope.

**ruff semantic model: what it does and does not do**
- `SemanticModel` (`model.rs` line 59) holds scopes, bindings, references, unresolved references, branches and definitions. It does not walk the AST itself. `push_scope` and `push_binding` are called by the linter's `Checker` in `ruff_linter/src/checkers/ast/mod.rs` (3,992 lines; `visit_stmt` at line 1048, scope pushes at 1390–1558, `add_binding` at 2813) — [crates/ruff_python_semantic/src/model.rs#L59](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/model.rs#L59), [crates/ruff_linter/src/checkers/ast/mod.rs#L1048](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_linter/src/checkers/ast/mod.rs#L1048)
- `resolve_qualified_name` (line 1212) resolves only an expression whose head is bound by an import, a builtin, or a class/function definition. For `BindingKind::Assignment` and the other binding kinds it returns `None`. So `s.commit()` with `s = Session()` is not resolved — [crates/ruff_python_semantic/src/model.rs#L1212](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/model.rs#L1212)
- Ruff fills that gap with "initializer typing": `trait TypeChecker { match_annotation; match_initializer }` and `check_type`, which inspect the binding's own statement (`x = init`, `x: T = …`, walrus, `with init as x`, an annotated parameter). The doc comment says it "doesn't perform more serious type inference" — [crates/ruff_python_semantic/src/analyze/typing.rs#L631-L700](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/analyze/typing.rs#L631)
- The FastAPI route check is Rust code. It matches a decorator `X.get/post/put/...` and resolves `X` with `typing::is_fastapi_route`, i.e. `X = FastAPI()` — [crates/ruff_linter/src/rules/fastapi/rules/mod.rs#L14-L51](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_linter/src/rules/fastapi/rules/mod.rs#L14), [analyze/typing.rs#L1144](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/analyze/typing.rs#L1144)
- Name reads return an explicit outcome enum, `ReadResult { Resolved(BindingId), ImplicitGlobal, WildcardImport, UnboundLocal(BindingId), NotFound }`, and unresolved references are kept with a `WILDCARD_IMPORT` flag — [model.rs#L3131](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/model.rs#L3131), [reference.rs#L155-L206](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/reference.rs#L155)
- The semantic model works on one file at a time. It turns `from x import y` into the qualified name `x.y` (and handles relative imports through `from_relative_import`), but it does not jump to the definition in another file. Cross-module resolution lives in ty: `ty_python_semantic` is about 236k lines and depends on salsa and `ruff_db` — [crates/ty_python_semantic/Cargo.toml](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ty_python_semantic/Cargo.toml)

### Inferences
- **Typed AST vs CST.** Mental's extract code is semantic: imports, assignments, calls, try/except, decorators. With ruff, `match stmt { Stmt::Try(StmtTry { handlers, .. }) => … }` is checked by the compiler, and a missing case is a compile error if wildcards are banned. With tree-sitter the same code becomes `node.kind() == "try_statement"` and `child_by_field_name("…")`, and a typo is a silent runtime miss. The algorithms in PyCG and in CodeQL's `flow.py` are written against CPython's `ast` and port almost line for line to ruff's AST. For "compact, understandable code", ruff wins.
- **Error recovery.** Both recover. Ruff returns a full AST plus an error list. Tree-sitter returns `ERROR` subtrees that every walker must skip. Neither is a reason to choose.
- **Compile cost and dependencies.** Tree-sitter is lighter in crates (21 vs 62) but needs a C toolchain and compiles a 3.4 MB C file. Ruff costs more crates but is pure Rust. Without a build measurement, treat this as a wash. Check it in the first spike with `cargo build --timings`.
- **API stability.** This is ruff's real cost. In four months, nodes Mental will touch (`ExprCall`, `ExprCompare`) changed shape. Mitigation: pin with `=0.0.N`, keep every ruff type inside `extract` (the facts are Mental's own `model` types), and bump on purpose with the snapshot suite as the safety net. Also, the 1.97 MSRV forces Mental's toolchain to follow ruff's.
- **Multi-language future.** Tree-sitter's uniform API looks like a multi-language win. But stack-graphs, the most ambitious attempt at language-agnostic resolution on tree-sitter, still needed 1,377 lines of Python-specific rules and was abandoned. Resolution and control-flow rules are per-language whatever the parser. The seam that matters is the `model` fact schema, not the parser. A second language later means a sibling module inside `extract` (e.g. `extract::js`) with whatever parser is best for that language.
- **Resolver.** For report-jobs, Mental needs: module symbol tables; imports turned into qualified names, including cross-module (`from app.db import Session`); local bindings (assignment, `with … as`, `for`, `except … as`, parameters); and "initializer types" driven by pack rules (`Session = sessionmaker(...)` → calling `Session()` gives `sqlalchemy.orm.Session`; `with Session() as s` → `s: Session`; `s.get(Report, id)` → `Report` instance; `app = FastAPI()`; `celery = Celery(...)`; `s3 = boto3.client("s3")`). That is a few hundred lines, mostly copying ruff's `check_type` idea. Reusing `ruff_python_semantic` would mean rewriting the Checker's binding walk anyway, plus 14 more crates, and it would still not resolve across modules.
- **SCIP / language server.** These add a Node runtime and an installed environment. That clashes with the local-first, no-hosted-infra constraint and with "facts only, deterministic". SCIP output is symbol occurrences, so call graph, control flow and effects would still need Mental's own code (inference; the SCIP proto was not read). Spec §6.2.1 currently says "tree-sitter" and "a SCIP indexer or a language server". Those two rows should be updated if this recommendation is accepted.

### Gaps
- Clean-build time and incremental compile time for ruff vs tree-sitter were not measured, because building was out of scope. This needs a spike.
- How often ruff bumps cause compile breaks in practice (not just diff size) is unmeasured. Track it in the first months.
- The SCIP protobuf schema and Pyright's binder (`binder.ts` code-flow graph) were not read. Claims about them are inferences from their READMEs and from general knowledge.
- Semgrep was not studied.

## How do these tools split the pipeline (parse → index → resolve → facts) so each stage is small and testable?

### Takeaway
The robust shape is: per-file stages (parse, index, local control flow) that never look at other files, then one cross-file resolution stage, then fact emitters that query the resolved model. Each stage produces data that can be inspected and snapshotted. PyCG shows the anti-pattern: one shared, mutable "manager" state that every pass changes, iterated to a fixpoint.

### Cited Findings
- **PyCG.** `analyze()` runs `PreProcessor` once, then repeats `PostProcessor` "while not has_converged()" (bounded by `max_iter`), then runs `CallGraphProcessor`. All passes share five mutable managers (`import_manager`, `scope_manager`, `def_manager`, `class_manager`, `module_manager`) — [pycg/pycg.py#L161-L215](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/pycg/pycg.py#L161)
- PyCG finds modules by installing a custom loader into `sys.path_hooks`, i.e. by driving Python's own import machinery — [pycg/machinery/imports.py#L214-L230](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/pycg/machinery/imports.py#L214)
- PyCG is archived: "Due to limited availability, no further development" — [README.md#L22](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/README.md)
- **ruff.** Parsing is a pure function from source to `Parsed`. Building the semantic model and running rules happen in a single traversal by `Checker`, which fills the model and calls the rules as it goes, so the model's state depends on the traversal position (the current `scope_id`, `node_id` and `branch_id` fields on `SemanticModel`) — [model.rs#L59-L120](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/model.rs#L59), [checkers/ast/mod.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_linter/src/checkers/ast/mod.rs)
- ruff's control-flow graph is a separate pure function, `build_cfg(stmts: &[Stmt]) -> ControlFlowGraph`, built on `IndexVec<BlockId, BlockData>` arenas with typed IDs (`newtype_index`) — [crates/ruff_python_semantic/src/cfg/graph.rs#L1-L60](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/cfg/graph.rs)
- **stack-graphs** is designed to be "efficient, incremental, and does not need to tap into existing build or program analysis tools": each file builds its own graph fragment, and resolution joins the fragments by path search — [README.md](https://github.com/github/stack-graphs/blob/fcb7705d5b38ae13b3665a9b2c882e5a97243d44/README.md)
- **CodeQL.** The extractor (in Python) writes the AST and control-flow graph into a database. Framework knowledge is a separate layer of QL classes over "API graphs", e.g. `API::moduleImport("fastapi").getMember("FastAPI").getReturn()`. Generic "concepts" (`Http::Server::RouteSetup`, `SqlExecution`, `FileSystemAccess`, `Http::Client::Request`) separate "what kind of effect" from "which library" — [python/extractor/semmle/python/passes/flow.py](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/extractor/semmle/python/passes/flow.py), [frameworks/FastApi.qll#L26-L35](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/frameworks/FastApi.qll#L26), [Concepts.qll#L85-L1065](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/Concepts.qll#L85)

### Inferences
Proposed stage layout for `extract`. Each stage is one module with a pure function and its own `tests.rs`:

| Stage | Input → output | Per-file? | Notes |
|---|---|---|---|
| `discover` | repo root → files with module names (from path, `__init__.py`) | — | The only file-system walker. No import hooks (unlike PyCG). |
| `parse` | source → ruff `Parsed` + syntax-error diagnostics | yes | `parse_unchecked`, never `parse_module`. |
| `index` | AST → `ModuleIndex` (top-level defs, imports as qualified names, module-level assignments with their initializer expressions, classes with bases) | yes | ruff-like binding kinds, minus the linter flags. |
| `resolve` | all `ModuleIndex` + pack type rules → `Resolved` (qualified name → definition or external; binding types; import graph) | **no**, the only cross-file stage | Bounded fixpoint over module-level bindings (PyCG's idea, but over immutable inputs, with a reported "did not converge" fact instead of a silent `max_iter`). |
| `flow` | one function's AST → obligations (branch points with labeled outgoing edges) | yes | Pure, like ruff's `build_cfg(&[Stmt])`. |
| `facts` | `Resolved` + per-function walk + packs → call sites, effects, state writes, entry points | — | Each fact kind is a small emitter over the same resolved view. |
| `compose` | `docker compose config` JSON → services, replicas, env, commands | — | Separate input, no Python. |

- Keep the arena + typed-ID style (ruff `IndexVec`/`newtype_index`) for definitions and bindings. It stays compact, needs no lifetimes, and serializes cleanly to JSON.
- Avoid ruff's single traversal that fills the model and runs rules at the same time. It makes each stage hard to test on its own. Mental has no rules to run during the traversal, so it can build first and query after.

### Gaps
- None of the studied tools publishes per-stage intermediate snapshots for Python call graphs. The idea of snapshotting each stage's output comes from ruff's parser and CFG tests, extrapolated.

## How are framework entry points and library effects kept as data rather than code?

### Takeaway
CodeQL's models-as-data is the template for Mental's packs. It uses rows of `(type, access path, kind)`, an access-path mini-language (`Member[x].ReturnValue.Argument[0,path:]`), and "type rows" that say how instances arise (`sqlalchemy.orm.Session` comes from `sqlalchemy.orm; Member[sessionmaker].ReturnValue.ReturnValue`). But CodeQL still writes routes and request handlers in QL code, and it has **no models at all** for Celery, boto3, click or Redis. Mental gets the format from CodeQL, must write the content itself, and has to extend the grammar for slots (decorators).

### Cited Findings
- The access-path grammar is spelled out in `ApiGraphModels.qll`. Columns are sources `type, path, kind`, sinks `type, path, kind`, summaries `type, path, input, output, kind`, barriers, and types `type1, type2, path`. Tokens include `Argument[n]` (ranges, `N-1`), `Parameter[n]`, `ReturnValue`, `WithArity[n]`, `Member[x]` (comma lists allowed), `Instance`, `Subclass`, `Awaited`, and more. "A type row of form `type1; type2; path` indicates that `type2; path` should be seen as an instance of the type `type1`". Synthetic types are prefixed with `~` — [python/ql/lib/semmle/python/frameworks/data/internal/ApiGraphModels.qll#L1-L70](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/frameworks/data/internal/ApiGraphModels.qll)
- A concrete pack file in YAML: sink rows like `['asyncpg.~Connection', 'Member[copy_from_query,execute,fetch,fetchrow,fetchval].Argument[0,query:]', 'sql-injection']` and type rows like `['asyncpg.Connection', 'asyncpg', 'Member[connect].ReturnValue.Awaited']`. ## How do they enumerate branches and exception paths, and how do they handle dynamic Python they cannot resolve?

### Takeaway
CodeQL's Python control-flow extractor is the best reference. Its edges are labeled NORMAL, TRUE, FALSE, EXCEPTION and EXHAUSTED. Expressions in general (including calls) get an exceptional edge, but cheap operations (attribute, name, subscript, for-iteration) get one only when lexically inside a `try`, which keeps graphs small. ruff's control-flow graph is an unfinished stub. On dynamic features: ruff reports explicit outcomes (`NotFound`, `WildcardImport`); PyCG silently drops calls it cannot resolve. Mental must do the former.

### Cited Findings
- CodeQL edge kinds: `NORMAL`, `TRUE`, `FALSE`, `EXCEPTION`, `EXHAUSTED` (lines 41–46). Each scope has an `exceptional_exit` node and an `exception_stack` (lines 621–637) — [python/extractor/semmle/python/passes/flow.py#L41](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/extractor/semmle/python/passes/flow.py#L41)
- `_walk_expr` (the generic walker, used for calls among others): "Many expressions can raise an exception" → always `_raise_exception` (line 1283). `_walk_attribute` raises only `if self.in_try` (line 1344). The same holds for names, subscripts, `yield` and for-loop iteration (line 1404) — [flow.py#L1283-L1350](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/extractor/semmle/python/passes/flow.py#L1283)
- `try` handling: `_walk_try` splits into try/finally and try/except. Each handler gets a "handler test" node whose failure propagates the exception to the next handler. "The next handler only sees unhandled exceptions from this handler". Exception groups (PEP 654) are handled separately — [flow.py#L1457-L1520](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/extractor/semmle/python/passes/flow.py#L1457)
- `with` is linear in the extractor (context expression → with node → target → body), and `match` has match/no-match successors per case — [flow.py#L1030-L1060](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/extractor/semmle/python/passes/flow.py#L1030)
- ruff's `build_cfg` has empty arms for `Stmt::While`, `For`, `If`, `Match`, `Try` and `With` (lines 203–256). Only `Return` and `Raise` have bodies, so it is not usable for branches — [cfg/graph.rs#L203-L256](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/cfg/graph.rs#L203)
- ruff tracks a separate "branch" tree (`BranchId` per arm of if/elif/else, with parent links) for its own analyses — [crates/ruff_python_semantic/src/branches.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/branches.rs)
- PyCG `visit_Call`: when `retrieve_call_names` returns nothing, it adds an edge only if the callee is an attribute with an external parent or a builtin, and otherwise `return`s with no record. A TODO admits the attribute-alias case fails ("import os; lala = os.path; lala.dirname()") — [pycg/processing/cgprocessor.py#L126-L160](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/pycg/processing/cgprocessor.py#L126)
- PyCG's "dynamic" micro-benchmark category has one case. Its expected call graph for `eval("func()")` records `<builtin>.eval` but not the call to `func` hidden in the string — [micro-benchmark/snippets/dynamic/](https://github.com/vitsalis/PyCG/tree/8d5dc40837803beef1d8d379fbf2cdad6cd94641/micro-benchmark/snippets/dynamic)
- ruff: `ReadResult::{Resolved, ImplicitGlobal, WildcardImport, UnboundLocal, NotFound}` and `DunderAllFlags::{INVALID_FORMAT, INVALID_OBJECT}` record when `__all__` cannot be read statically — [model.rs#L3131](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/model.rs#L3131), [model/all.rs#L10-L18](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/model/all.rs#L10)
- CodeQL `RouteSetup.getUrlPattern()` holds only when the argument's local source is a string literal. A non-literal yields no value; it does not guess — [Concepts.qll#L966-L972](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/Concepts.qll#L966)

### Inferences
- Mental needs obligations (branch points), not a full CFG. A fixed table of AST forms, each with labeled outcomes, is enough:
  - `if`/`elif`/`else` → true/false
  - conditional expression → true/false; report-jobs has one in `tasks.py`
  - boolean `and`/`or` inside a condition → recorded as the condition's structure, not separate obligations (open design choice)
  - `while`/`for` → enter/exhausted (+ `break`)
  - `try` → one edge per handler + none-raised (+ `else`/`finally` flags)
  - `match` → one per case + no-match
  - `assert` → holds/fails
  - early `return`/`raise` → recorded as exits
- Exception edges, following CodeQL's economy:
  1. explicit `raise`
  2. inside a `try`, every call becomes a "may raise X" candidate for each handler whose type resolves (e.g. `except OperationalError` around `generate_report.delay`, `except ClientError` around `s3.put_object`)
  3. outside a `try`, no per-call edges; only "this function may raise" from pack `raises` rows (e.g. `Task.retry` raises `celery.exceptions.Retry`)
- Unresolvable things become facts, never silence:
  - `unresolved{reason: not_found | wildcard_import | dynamic_attr (getattr with non-literal) | eval | dynamic_import (importlib/__import__) | ambiguous(n) | no_pack(qualified name)}`
  - This applies to call sites, decorators, config values (`os.environ["X"]` → an `env` fact, not a value) and route paths.
  - Spec P7 says extractors "never guess dynamic behavior". This is how that rule shows up in the data.

### Gaps
- None of the studied tools enumerates "obligations" as Mental defines them (branch + coverage duty). The mapping from control-flow edges to obligations is Mental's own design.
- Python's implicit exceptions from `with` (`__exit__`) and generators are modeled by CodeQL in ways not read in full here.

## What test strategies do they use, and how would Mental reuse them against examples/report-jobs?

### Takeaway
Four proven patterns fit Mental:
1. Inline expectations written as comments in the fixture, with `MISSING:`/`SPURIOUS:` markers for known gaps (CodeQL).
2. Multi-file fixtures in one file with `# --- path: x.py ---` separators and caret assertions (stack-graphs).
3. Categorized micro-benchmarks: `main.py` + expected JSON + a one-line README (PyCG).
4. Directory-driven insta snapshots of whole outputs and of per-function graphs rendered as text (ruff parser and CFG tests).

ty's Markdown mdtest is elegant but needs a 1.9k-line harness, which is bloat for Mental.

Copy:** the benchmark categories and their file layout, and the harness being generic over the generator ([micro-benchmark/](https://github.com/vitsalis/PyCG/tree/8d5dc40837803beef1d8d379fbf2cdad6cd94641/micro-benchmark)). **Avoid:** silent drops in `visit_Call` ([cgprocessor.py#L144-L155](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/pycg/processing/cgprocessor.py#L144)); shared mutable managers and an open-ended fixpoint ([pycg.py#L161](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/pycg/pycg.py#L161)); `sys.path_hooks` ([imports.py#L214](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/pycg/machinery/imports.py#L214)).
- **CodeQL. Copy:** the MaD row format and access-path tokens ([ApiGraphModels.qll](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/frameworks/data/internal/ApiGraphModels.qll)); type rows for instance creation ([Asyncpg.model.yml](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/frameworks/Asyncpg.model.yml)); generic concepts ([Concepts.qll](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/Concepts.qll)); edge kinds and exception edges guarded by `in_try` ([flow.py](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/extractor/semmle/python/passes/flow.py)); inline expectations with `MISSING:`/`SPURIOUS:` ([InlineExpectationsTest.qll](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/shared/util/codeql/util/test/InlineExpectationsTest.qll)). **Avoid:** the parts of framework models that live in code (routes in QL); taint-oriented kinds (`sql-injection`) where Mental needs effect kinds; a general type-tracking engine.

- The cheapest high-value import is CodeQL's data model. The cheapest high-value test idea is stack-graphs' and CodeQL's comment assertions. Neither brings a dependency.

## Candidate guidelines for `extract` (enforceable rules)

### Takeaway
Twenty rules, each tied to evidence and to a concrete enforcement mechanism. Together they keep `extract` small (pure stages, no library names in Rust), honest (explicit unresolved facts, exhaustive obligation kinds), and well-tested (inline-expectation fixtures, whole-output snapshots, oracle and property tests).

### Cited Findings
Each rule gives **Rule / Why / Source / Enforce**.

1. **Parser.** Use `ruff_python_parser` + `ruff_python_ast` (+ `ruff_text_size`, `ruff_source_file`) pinned with `=0.0.N`. No `ruff_python_semantic`, `ty_*`, tree-sitter, stack-graphs or SCIP in version one. *Why:* typed AST, pure Rust, CPython-shaped nodes. Semantic and ty are coupled to the linter or too large. *Source:* §1 above. *Enforce:* a CI check that greps `Cargo.toml` for `=` pins on `ruff_*`; `cargo deny` bans the other crates; reviewer.
2. **No ruff types escape `extract`.** Public functions take paths and strings and return `model` types. *Why:* weekly breaking releases (`ExprCompare`/`ExprCall` changed within four months) must stay contained. *Source:* [versioning.md](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/docs/versioning.md), the local churn measurement. *Enforce:* `unreachable_pub` lint; a CI check that `cargo tree -p model -p mentalc -p mentalvm -i ruff_python_ast` finds nothing.
3. **Bump ruff on purpose.** A bump is a single commit that touches only `extract`, with every snapshot passing unchanged or the changes reviewed. *Source:* the churn measurement. *Enforce:* a CI check on the PR diff (a `Cargo.lock` ruff change plus files outside `crates/extract` = fail); reviewer.
4. **Always `parse_unchecked`.** Every syntax error becomes an anchored `diagnostic` fact, and extraction continues on the recovered tree. *Source:* [lib.rs#L289](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_parser/src/lib.rs#L289); fail rather than degrade still applies to missing *inputs*. *Enforce:* clippy `disallowed_methods` for `ruff_python_parser::parse_module`; a proptest that feeds every prefix of every fixture file and asserts no panic and at least one diagnostic when `has_syntax_errors()`.
5. **One stage per module, pure functions.** `discover` and `compose` are the only modules that do I/O (file system, subprocess). *Source:* the pipeline section; ruff `build_cfg(&[Stmt])`. *Enforce:* clippy `disallowed_methods`/`disallowed_types` for `std::fs::*` and `std::process::*` via `clippy.toml`, allowed only in those modules with `#[expect]`; reviewer.
6. **Per-file stages never see other files.** `parse`, `index` and `flow` take one file. Only `resolve` is cross-file. *Why:* testability, and incremental builds later (stack-graphs' principle). *Source:* [stack-graphs README](https://github.com/github/stack-graphs/blob/fcb7705d5b38ae13b3665a9b2c882e5a97243d44/README.md). *Enforce:* signatures (`fn index(file: &ParsedFile) -> ModuleIndex`); reviewer.
7. **Every lookup returns an outcome enum, never `Option`.** `Resolved(id) | External(qualified_name) | Unresolved(Reason)`, with `Reason` a closed enum: `not_found`, `wildcard_import`, `dynamic_attr`, `eval`, `dynamic_import`, `ambiguous`, `no_pack`, `not_converged`. *Source:* ruff [`ReadResult`](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/model.rs#L3131); PyCG's silent drop as the counterexample ([cgprocessor.py#L144](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/pycg/processing/cgprocessor.py#L144)). *Enforce:* reviewer; plus rule 8's oracle test.
8. **Conservation.** Every call expression, decorator and branch form in the AST appears in the output exactly once, resolved or not. *Why:* this is the rule that makes "complete" checkable (spec P7: extractors own completeness). *Enforce:* an oracle test. A separate ~30-line `Visitor` counts `Expr::Call`, decorators and branch statements per file, compares the counts with the emitted facts on every fixture and on report-jobs, and runs under proptest on generated programs.
9. **Extract never guesses.** No heuristic edges, no name-similarity matching, no "most likely" type. Guesses belong to Link and are marked `heuristic` there. *Source:* spec P7, §6.2.2; CodeQL's literal-only `getUrlPattern` ([Concepts.qll#L966](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/Concepts.qll#L966)). *Enforce:* the `model` fact schema for `extract` has no `heuristic` field; reviewer.
10. **Types come only from initializers and annotations.** A binding's type comes from its own statement (assignment, `with … as`, parameter or variable annotation) combined with pack type rows. The cross-module fixpoint is bounded, and a binding that has not converged gets an `unresolved(not_converged)` fact. *Source:* ruff [`check_type`](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/analyze/typing.rs#L643); CodeQL type rows; PyCG fixpoint, made explicit. *Enforce:* fixtures in an `assignments/` category; reviewer rejects flow-sensitive inference.
11. **No library names in Rust.** Framework and library knowledge lives only in pack data files. *Source:* spec §7 ("Packs are declarative data"); CodeQL MaD; ruff's FastAPI-in-Rust as the counterexample. *Enforce:* a CI check that greps `crates/extract/src` (excluding `tests`) for `fastapi|celery|sqlalchemy|boto|click|redis|requests|kombu|pydantic` and fails on a match.
12. **One small, closed access-path grammar for packs.** Tokens: `Member[a,b]`, `ReturnValue`, `Argument[i,name:]`, `Parameter[i]`, `Instance`, `Subclass`, plus Mental's `Decorates` and `WithArg[i=literal]`. Row kinds: `type`, `effect`, `slot`, `raises`, `config`. An unknown token or kind is a pack load error. *Source:* [ApiGraphModels.qll](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/frameworks/data/internal/ApiGraphModels.qll). *Enforce:* parser unit tests; proptest round-trip (parse ∘ print = id); fail-rather-than-degrade on unknown tokens.
13. **Effect kinds are generic.** `db.read`, `db.write`, `tx.end`, `send:<channel>`, `http`, `file.read`, `file.write`, `clock`, `env`, never library names. *Source:* CodeQL concepts ([Concepts.qll](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/Concepts.qll)). *Enforce:* a closed enum in `model`; serde rejects unknown values.
14. **Obligation kinds come from an exhaustive `match`.** Every `Stmt` and `Expr` variant is classified explicitly. *Why:* a new ruff node kind must fail the build, not vanish silently. *Source:* ruff's half-done `build_cfg` shows how missing arms hide. *Enforce:* `#![deny(clippy::wildcard_enum_match_arm)]` on the `flow` module.
15. **Exception edges follow CodeQL's economy.** Edges come from explicit `raise`, from calls inside a `try` for each handler, and from pack `raises` rows. There are no per-call exception edges outside a `try`. Edge labels: `true`, `false`, `exception(type)`, `exhausted`, `normal`. *Source:* [flow.py#L41, L1283, L1344, L1457](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/extractor/semmle/python/passes/flow.py#L1283). *Enforce:* one fixture per rule in `control_flow/` and `exceptions/`; obligation snapshots.
16. **Every fact carries an anchor.** File, byte range (`TextRange`), and 1-based line:column for display. *Source:* spec P8; ruff ranges on every node ([generated.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_ast/src/generated.rs#L9465)). *Enforce:* a non-optional `anchor` field in `model`; a test that every anchor's range slices to non-empty source text.
17. **Output is deterministic.** Facts are sorted by (file, offset, kind). No `HashMap` iteration reaches the output. *Source:* ruff lint `iter_over_hash_type` ([Cargo.toml#L306](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/Cargo.toml#L306)). *Enforce:* `#![deny(clippy::iter_over_hash_type)]`; a test that runs extract twice on report-jobs and requires byte-identical JSON.
18. **Fixtures use inline expectations.** One `.py` file per case. Multi-file cases use `# --- path: … ---` fragments. Expectations are written as `# $ tag=value` on the line of the source construct, or as `# ^ tag=value` caret lines for column precision; known gaps as `MISSING:`/`SPURIOUS:`. The harness is at most ~200 lines and discovers files with `insta::glob!`. *Source:* [stack-graphs test.rs](https://github.com/github/stack-graphs/blob/fcb7705d5b38ae13b3665a9b2c882e5a97243d44/tree-sitter-stack-graphs/src/test.rs#L14), [CodeQL InlineExpectationsTest.qll](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/shared/util/codeql/util/test/InlineExpectationsTest.qll), [PyCG categories](https://github.com/vitsalis/PyCG/tree/8d5dc40837803beef1d8d379fbf2cdad6cd94641/micro-benchmark/snippets). *Enforce:* the harness fails on any unmatched expectation or unexpected fact for a tag in use, and reports "fixed MISSING" as a failure so the marker gets removed; reviewer requires a fixture for each new fact kind.
19. **report-jobs is the acceptance test.** A full-output `insta::assert_json_snapshot!` plus explicit count assertions (files, entry points by kind, state variables, call edges once the edge definition is written down). An annotated fragment copy carries inline expectations, and a drift test compares it with `examples/report-jobs/src`. *Source:* spec §6.2.1 and F-S10; ruff whole-output snapshots. *Enforce:* CI test; reviewer approves snapshot diffs.
20. **Out of scope for version one.** No CST or trivia, no incremental reparsing, no LSP, no salsa or query engine, no generic multi-language abstraction layer, no taint tracking. Language-specific code lives under `extract::python`, and a second language later is a sibling module emitting the same `model` facts. *Why:* stack-graphs and ty show where this ends (archived; 236k lines). *Source:* §1 above. *Enforce:* `cargo deny` bans `salsa`, `tree-sitter*` and `lsp-*`; reviewer.

### Inferences
- Rules 8 (conservation oracle), 11 (no library names in Rust) and 14 (no wildcard arms) are the most valuable per line of enforcement. Each is a short check that catches whole classes of silent incompleteness, which is exactly the failure mode spec P7 assigns extractors to prevent.
- Spec §6.2.1 should be amended. Parse "with tree-sitter" should become ruff's parser, and "Resolve names with a SCIP indexer or a language server" should become Mental's own resolver driven by pack type rows. Record the decision with this note as evidence and keep the tree-sitter alternative listed as "Experiment" with a trigger: if ruff churn costs more than about one hour per month, or a second language is scheduled.

### Gaps
- Rule 4's proptest and rule 8's oracle have no precedent in the studied tools. They are proposals.
- The exact definition of a "call-graph edge" behind F-S10's "41 edges" is not in the spec. Rule 19's count assertion for edges depends on writing it down.
