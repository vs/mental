# Pure Cores and Recorded Choices Keep Mental Small

The mature codebases agree on one shape, and it fits all four of Mental's crates: a core that does no I/O and returns `(value, diagnostics)`, a thin shell that owns files, clocks, subprocesses and the LLM, plain data at every boundary, and every source of nondeterminism turned into a recorded, replayable value. They also show where the size of a codebase comes from: frameworks (Salsa, rmcp, stack-graphs, tree-sitter's untyped trees), generality nobody asked for (twelve output formats, five hash modes, a dozen search strategies), and leniency that hides errors (skipping unknown fields, dropping unresolved calls). Tests follow the same logic: data-driven fixtures through one helper per module, inline expectations in source fixtures, a dumb reference implementation beside every clever algorithm, recorded LLM answers instead of live calls, and mutation testing plus coverage on the diff.

## How this report was made

Six notes back this report, one per question: the record format ([model_record_format.md](notes/model_record_format.md)), the Python extractor ([extract_static_analysis.md](notes/extract_static_analysis.md)), the compiler's architecture ([mentalc_architecture.md](notes/mentalc_architecture.md)), the LLM loop and MCP server ([mentalc_llm_loop_mcp.md](notes/mentalc_llm_loop_mcp.md)), the interpreter ([mentalvm_model_checking.md](notes/mentalvm_model_checking.md)) and testing ([testing_strategy.md](notes/testing_strategy.md)). Every project was shallow-cloned on 13–14 November 2026 and read at a pinned commit; nothing was built or run inside a clone. Dependency counts come from `cargo tree` in a separate probe project, and line counts from `wc -l`. Each note separates what the source shows from what the researcher inferred for Mental, and this report keeps that line: where no studied project does something, the text says the recommendation is derived.

## One architecture repeats in all four crates

### The core never touches the world, and problems are data

rust-analyzer states the rule most plainly: its core "doesn't interact with the outside world and thus can't fail", and analyses "compute `(T, Vec<Error>)` rather than `Result<T, Error>`"; even the parser "never fails" ([rust-analyzer architecture.md L451-457](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/docs/book/src/contributing/architecture.md#L451)). typst goes one step further and routes **every** external access through `trait World`, including the current date, so the compiler crates never see the file system or the clock ([typst lib.rs L63-101](https://github.com/typst/typst/blob/84cca406aafe7f830ed3f37f1cc6f0c8b6b65a03/crates/typst-library/src/lib.rs#L63)). For Mental this means a problem found in the analyzed repository (a syntax error, an unresolved call, a guard overlap) is a diagnostic value, never an `Err`. Only the shell, which reads files, calls the LLM and writes `.mental/`, returns `Result`, with typed `thiserror` errors at the I/O functions and `anyhow` context in the binary.

The pipeline itself is a plain function. typst's `compile_impl` is a straight sequence of calls with one bounded relayout loop and no phase registry ([typst lib.rs L100-140](https://github.com/typst/typst/blob/84cca406aafe7f830ed3f37f1cc6f0c8b6b65a03/crates/typst/src/lib.rs#L100)); jaq spells its whole pipeline out as four steps in the crate doc ([jaq-core lib.rs](https://github.com/01mf02/jaq/blob/c6cc7d3721ccfb212f153006c4fc90c56567540c/jaq-core/src/lib.rs#L1)); rust-analyzer's style guide forbids "doer" objects in favor of `do_thing(arg1, arg2)` ([style.md L350-404](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/docs/book/src/contributing/style.md#L350)). Mental's `mentalc` has exactly twelve phases in a fixed order ([spec §6.2](../../specification.md#4-the-build-at-a-glance)), so a `Phase` trait or pass manager would only hide the data flow that the spec's Reads and Writes columns already make explicit.

### Serializable types are promises, so only the record format has them

rust-analyzer keeps its internal types non-serializable by design, because "if a type is serializable, then it is a part of some IPC boundary" and carries compatibility constraints ([architecture.md L505-517](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/docs/book/src/contributing/architecture.md#L505)); ruff renders JSON from a separate view struct rather than its internal `Diagnostic` ([ruff render/json.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_db/src/diagnostic/render/json.rs#L47)). In Mental the files between the tools *are* the IPC boundary ([spec §3](../../specification.md#3-three-tools)), so `Serialize`/`Deserialize` belong in `model` (records, anchors, diagnostics, ledger lines, run files) and in `mentalc`'s CLI views, and nowhere else. Syntax trees, resolver tables and planner structs stay private. The crate graph follows: `model` depends on no workspace crate, `extract` on `model`, `mentalc` on `model` and `extract`, `mentalvm` on `model`, and `mentalc` and `mentalvm` never on each other.

### The rules that keep the shape are mostly checkable by machine

About a third of rust-analyzer's style can be enforced mechanically, and it enforces those parts as ordinary tests: `xtask/src/tidy.rs` rejects `#[should_panic]`, checks `Cargo.toml` hygiene and licenses, and runs under `cargo test`, because "there's no additional checks in CI" ([tidy.rs L83-220](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/xtask/src/tidy.rs#L83)). Its workspace lints deny clippy's `correctness` and `perf` groups and warn on `dbg_macro`, `todo`, `print_stdout` and `print_stderr`, raised to errors in CI ([Cargo.toml L174-237](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/Cargo.toml#L174)); ruff adds `iter_over_hash_type`, which keeps hash-map order out of output ([ruff Cargo.toml L270-320](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/Cargo.toml#L270)). The proposed Mental rules below combine these. The use of `disallowed_methods` to fence I/O into named modules is derived: the lint and per-module `#[allow]` are standard, but no studied repository configures exactly this.

| Rule | Enforcement |
|---|---|
| Pure cores: no `std::fs`, `std::process::Command`, `std::env::var`, `SystemTime::now`, `Instant::now` or `std::thread::spawn` outside the shell modules (`repo.rs`, `cache.rs`, `backend/`, `cli/` in `mentalc`; `discover` and `compose` in `extract`; nothing in `mentalvm`'s core) | `clippy.toml` `disallowed-methods`, scoped `#[allow]` in shell modules, CI `-D warnings` |
| No `HashMap`/`HashSet` where order can reach output (`model`, `mentalvm` core, `extract` facts) | `disallowed-types`; `iter_over_hash_type`; a determinism test that runs twice and compares bytes |
| `Serialize` derives only in `model` and `mentalc::cli` | tidy test that greps derives |
| Fixed crate graph | tidy test that parses each `Cargo.toml` (rust-analyzer's `check_cargo_toml` pattern) |
| `unsafe_code = "forbid"`, `unreachable_pub`, no `#[non_exhaustive]` on internal enums (it forces wildcard arms that hide missing cases) | workspace lints; `wildcard_enum_match_arm` in modules that classify AST or outcome variants |
| No `#[should_panic]`, no `#[ignore]`; assert the current wrong behavior with a FIXME instead | tidy test, following [rust-analyzer style.md L163-265](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/docs/book/src/contributing/style.md#L163) |
| A dependency budget: every new crate, transitive ones included, is a written decision | a test that diffs `Cargo.lock` package names against a checked-in list ("read Cargo.lock", [style.md L55-62](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/docs/book/src/contributing/style.md#L55)) |
| Reviewer checklist: functions over doer objects; split functions that take literal `bool`/`Option` arguments; `Config` structs without `Default`, passed explicitly; public fields unless there is an invariant; no setters; no generics across crate boundaries | PR template, from [style.md L267-625](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/docs/book/src/contributing/style.md#L267) |

Some rust-analyzer habits are deliberately left out. Its `never!` soft assertions and per-request `catch_unwind` exist because a language server must not die; a batch compiler should assert and fail. The same goes for ruff's custom allocators, panic hook and argument-file expansion.

## `model`: one canonical text form for every ID and every line

### An ID is valid when parsing and printing give back the same bytes

SCIP defines a valid symbol by round trip: its `lint` parses each symbol, formats it again, and reports `nonCanonicalSymbolError` when the two differ ([scip lint.go L249-264](https://github.com/sourcegraph/scip/blob/be1d9f769a02a11be3b3ec5485231e2531a78a1c/cmd/scip/lint.go#L249-L264)). SCIP also shows the bug this rule exists to catch: its Rust formatter escapes anything not ASCII-alphanumeric while its parser accepts unescaped Unicode letters, and its Go binding is ASCII-only, so the bindings accept different languages ([scip symbol.rs L296-324](https://github.com/sourcegraph/scip/blob/be1d9f769a02a11be3b3ec5485231e2531a78a1c/bindings/rust/src/symbol.rs#L296-L324); [identifier.go](https://github.com/sourcegraph/scip/blob/be1d9f769a02a11be3b3ec5485231e2531a78a1c/bindings/go/scip/identifier.go#L3-L5)). SCIP needs two escaping schemes only because its names are arbitrary user text. Mental builds slugs itself from code names ([spec §4.3](../../specification.md#72-semantic-ids)), so it can fix the alphabet to `[a-z0-9]+(-[a-z0-9]+)*`, never escape anything, and use **one** character-class function in the slugifier, the parser and the validator.

The Rust shape that keeps this honest is small. `text-size` hides its field and validates inside `Deserialize`, returning `invalid range: {start}..{end}` with a test on the exact message ([serde_impls.rs](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/lib/text-size/src/serde_impls.rs); [tests/serde.rs L40-50](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/lib/text-size/tests/serde.rs#L40-L50)), and cargo-platform implements `Serialize` through `Display` and `Deserialize` through `FromStr` ([cfg.rs L132-230](https://github.com/rust-lang/cargo/blob/382ecb8707b82592bb7176ba62b07590c29dee35/crates/cargo-platform/src/cfg.rs#L8-L16)). Mental's `Id` is therefore a private `String` built only by `Id::parse` or `Id::child(kind, slug)`, with a closed `Kind` enum for the prefixes (`port`, `beh`, `pred`, `case`, `n`, …) so that a reference's type check is a prefix check, as Glean checks that a referenced fact has the expected predicate ([validate.cpp L66-89](https://github.com/facebookincubator/Glean/blob/bdc9a9235e0af30434f02c0b6515247576444ea8/glean/rts/validate.cpp#L66-L89)). Kythe's naming rule settles what may go into an ID: "a name should say 'what' something is, not 'when'" ([storage.proto L85-90](https://github.com/kythe/kythe/blob/69141f022689a611e8a4a1d9b08a3783a2e8a9ed/kythe/proto/storage.proto#L85-L90)), so no positions, counters, hashes or versions, which the spec already requires. When two code names collide, cargo's lockfile shows the stable fix: add a qualifier only when needed, never an index ([lockfile.rs L210-212](https://github.com/rust-lang/cargo/blob/382ecb8707b82592bb7176ba62b07590c29dee35/crates/cargo-util-schemas/src/lockfile.rs#L210-L212)). Glean's identity rule turns P9 into a check: a duplicate key with an equal value returns the existing fact, and a duplicate key with a different value is an error ([factset.cpp L278-293](https://github.com/facebookincubator/Glean/blob/bdc9a9235e0af30434f02c0b6515247576444ea8/glean/rts/factset.cpp#L278-L293)).

Arenas and interners are bloat at this scale. `la-arena` and rust-analyzer's `PathInterner` pay off for millions of short-lived IDE items and pull in `indexmap` and `rustc-hash` ([path_interner.rs](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/crates/vfs/src/path_interner.rs)). A model of a few thousand records fits in one `Vec<T>` per kind, sorted by `Id`, searched with `binary_search_by`, which is what SCIP does with canonicalized symbol lists ([sort.go](https://github.com/sourcegraph/scip/blob/be1d9f769a02a11be3b3ec5485231e2531a78a1c/bindings/go/scip/sort.go#L25)). The "few thousand" figure comes from the report-jobs example, not from measurement.

### The model is a single-writer artifact, so it takes Cargo.lock's discipline

Shared formats with many writers (protobuf in SCIP and Kythe, the cargo registry index) evolve by ignoring what they do not understand; the cargo index skips any line it cannot parse ([index/mod.rs L577-600](https://github.com/rust-lang/cargo/blob/382ecb8707b82592bb7176ba62b07590c29dee35/src/sources/registry/index/mod.rs#L577-L600)). Cargo.lock, a derived file owned by one tool, does the opposite: a `version` marker makes old Cargo "give a formal error", the emitter is hand-written for an exact layout with sorted packages, the file is rewritten only when its content differs, and the early catch-all `[metadata]` map "is nowadays sort of deemed a bad idea" ([encode.rs](https://github.com/rust-lang/cargo/blob/382ecb8707b82592bb7176ba62b07590c29dee35/src/resolver/encode.rs); [ops/lockfile.rs L138-243](https://github.com/rust-lang/cargo/blob/382ecb8707b82592bb7176ba62b07590c29dee35/src/ops/lockfile.rs#L138-L243)). Mental's model is "derived, never edited by hand and never merged" ([spec §4.9](../../specification.md#75-storage)), which is the Cargo.lock case. So every record struct carries `#[serde(deny_unknown_fields)]`; there is one model-wide format version, and a mismatch is a hard error that says "rebuild"; there is no migration code and no `extra` map. Lines are sorted bytewise by ID, fields appear in declaration order, `None` and empty sets are omitted, and every file ends with a newline. Glean's design guide supplies the per-field rule: if order has no meaning, store a sorted set, because a forced array is "non-deterministic which leads to spurious differences in things like test outputs" ([design.md](https://github.com/facebookincubator/Glean/blob/bdc9a9235e0af30434f02c0b6515247576444ea8/glean/website/docs/schema/design.md)).

Validation is one pure, whole-set pass. Glean checks range, expected type, order and key uniqueness for every reference ([validate.cpp L50-140](https://github.com/facebookincubator/Glean/blob/bdc9a9235e0af30434f02c0b6515247576444ea8/glean/rts/validate.cpp#L66-L89)); SCIP collects every error into a set and deduplicates and sorts it ([lint.go L414-435](https://github.com/sourcegraph/scip/blob/be1d9f769a02a11be3b3ec5485231e2531a78a1c/cmd/scip/lint.go#L414-L435)); Kythe's `ValidEntry` returns the first error only, which is the pattern to avoid ([graphstore.go L134-147](https://github.com/kythe/kythe/blob/69141f022689a611e8a4a1d9b08a3783a2e8a9ed/kythe/go/services/graphstore/graphstore.go#L134-L147)). Mental's `check(&Model) -> Vec<Diagnostic>` should report, for every reference field, whether it parses, exists, has the expected kind and has an existing parent, plus duplicate IDs and unsorted sets, and sort the result by `(id, code, field)` rather than by message text, so that rewording a message does not reorder output. The diagnostic is itself a record in `diagnostics.jsonl` that `mentalvm` and `mentaldbg` read, so it lives in `model`: a closed `Code` enum with stable kebab-case names, a severity of `error`, `warning` or `info` (typst gets by with two, [diag.rs L427-454](https://github.com/typst/typst/blob/84cca406aafe7f830ed3f37f1cc6f0c8b6b65a03/crates/typst-library/src/diag.rs#L427)), the record ID, a JSON-path field, the message, and the spec's anchor (file, lines, quote) instead of byte spans, because Mental anchors must survive being re-read by an LLM.

### Guards stay tiny: three operators, full IDs, and enumeration up to 16 predicates

cargo-platform's expression type is a six-variant enum with a hand-written recursive-descent parser of about 100 lines and an evaluator of about 10, and it rejects trailing input instead of silently stopping early ([cfg.rs L166-290](https://github.com/rust-lang/cargo/blob/382ecb8707b82592bb7176ba62b07590c29dee35/crates/cargo-platform/src/cfg.rs#L166-L175)). cfg-expr evaluates over a `Logic` trait implemented for `bool` and for `Option<bool>` as Kleene logic ([expr.rs L735-826](https://github.com/EmbarkStudios/cfg-expr/blob/7e43423c5e32b24f9da0ff65cf3cad5d07bfada9/src/expr.rs#L735-L826)). Mental's guards need `!`, `&`, `|`, parentheses and predicate IDs, nothing more. The three-valued evaluator does double duty: the checker uses `bool`, and the interpreter uses `Option<bool>` for the spec's "ordered reads" rule, where a predicate is unknown until the node that decides it ([spec §4.7](../../specification.md#74-record-kinds)). That argues for putting `Expr` and its evaluator in `model`, shared by `mentalc` and `mentalvm`. boolean_expression shows the trap to avoid: it treats a variable missing from the assignment as `false` ([expr.rs L129-137](https://github.com/cfallin/boolean_expression/blob/795b89567e05f54907b89453bdd481d0b01f0c93/src/expr.rs#L129-L137)), which in Mental would turn a typo into a silently unreachable case. An unknown predicate is a link error.

For the partition check (cover everything, never overlap), the most compact correct algorithm is enumeration: map the n distinct predicates a behavior's guards mention to bits, evaluate every guard for each of the 2^n masks, and report the lowest mask with zero true guards as a gap and the lowest with two or more as an overlap, naming the predicates. That is about 15 lines and gives concrete messages. At n = 16 and 30 guards it is about 10^7 node evaluations; this is arithmetic, not a benchmark. Above the cap the checker emits `guard-check-too-large` rather than skipping, per the owner's fail-rather-than-degrade rule; a 40-line Kleene case split behind the same signature is the upgrade path. BDD libraries are 2,400 to 10,600 lines with dependencies outside Mental's allowed set ([biodivine Cargo.toml](https://github.com/sybila/biodivine-lib-bdd/blob/f2c39b81630d4fd1e3e51245c0dfebf11855811e/Cargo.toml#L22-L28)). One real problem has no precedent in the studied crates: predicates over one enum state variable (`status-is-pending`, `status-is-done`) are not independent, so plain enumeration reports impossible overlaps and gaps. The spec needs a rule, such as declaring such predicates "exactly one" groups and skipping infeasible masks, before this check is written.

## `extract`: ruff's parser, Mental's resolver, CodeQL's data model

### A typed AST beats an untyped tree for semantic extraction, at the cost of churn

ruff's parser crates are on crates.io as `0.0.x` releases, one per week, currently 0.0.22 of 12 November 2026, with the explicit warning that they provide "**no stability guarantees**" ([ruff versioning.md](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/docs/versioning.md); [crates.io](https://crates.io/crates/ruff_python_parser)). The parser is hand-written recursive descent; `parse_unchecked` always returns a full AST with the syntax errors listed beside it ([lib.rs L112-470](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_parser/src/lib.rs#L112)), and the AST is typed and CPython-shaped, so `Stmt::Try(StmtTry { handlers, .. })` is checked by the compiler ([generated.rs L9465](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_ast/src/generated.rs#L9465)). tree-sitter-python yields a CST of 218 node types accessed by kind strings ([node-types.json](https://github.com/tree-sitter/tree-sitter-python/blob/26855eabccb19c6abf499fbc5b8dc7cc9ab8bc64/src/node-types.json)), where a typo is a silent runtime miss. The algorithms worth porting (PyCG's, CodeQL's `flow.py`) are written against CPython's `ast` and transfer almost line for line to ruff's.

The costs are real and should be stated with the recommendation. Between ruff 0.16.0 and 0.17.5 (four months), 119 files in the AST and parser changed (+4,781/−3,795 lines), including `ExprCompare` and `ExprCall`, which Mental will touch; the crates force MSRV 1.97; and parser plus AST resolve to **62 crates** against **21** for tree-sitter plus a C toolchain (local `cargo tree` measurements in the note). Compile time was not measured. The mitigation is containment: pin with `=0.0.N`, keep every ruff type inside `extract` so public functions return only `model` types, and bump ruff in a commit that touches only `extract`, with the snapshot suite as the safety net. Depending on `ruff_python_semantic` does not help: its `SemanticModel` is filled by the linter's 3,992-line `Checker`, and `resolve_qualified_name` returns `None` for assignment bindings, so `s = Session(); s.commit()` stays unresolved ([model.rs L1212](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/model.rs#L1212)). Cross-module resolution lives in ty, a 236k-line salsa crate ([ty Cargo.toml](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ty_python_semantic/Cargo.toml)). Mental's own resolver, covering module symbol tables, imports as qualified names, local bindings, and initializer typing driven by pack type rows (copying ruff's `check_type` idea, [typing.rs L631-700](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/analyze/typing.rs#L631)), is estimated at a few hundred lines. The multi-language argument for tree-sitter is weaker than it looks: stack-graphs, the most ambitious language-agnostic resolver on tree-sitter, still needed a 1,377-line Python rules file and is archived ([stack-graphs README](https://github.com/github/stack-graphs/blob/fcb7705d5b38ae13b3665a9b2c882e5a97243d44/README.md)). The seam that matters for a second language is the `model` fact schema, not the parser.

### Per-file stages, one cross-file stage, and every lookup returns an outcome

PyCG is the anti-pattern: all passes mutate five shared managers until a convergence check passes ([pycg.py L161-215](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/pycg/pycg.py#L161)), and when it cannot resolve a call it simply returns with no record ([cgprocessor.py L126-160](https://github.com/vitsalis/PyCG/blob/8d5dc40837803beef1d8d379fbf2cdad6cd94641/pycg/processing/cgprocessor.py#L126)). ruff's name reads return an explicit outcome, `ReadResult { Resolved, ImplicitGlobal, WildcardImport, UnboundLocal, NotFound }` ([model.rs L3131](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/model.rs#L3131)), and CodeQL fills a route's URL pattern only when the argument is a string literal ([Concepts.qll L966-972](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/Concepts.qll#L966)). Spec P7 says extractors never guess ([spec P7](../../specification.md#2-principles)); in the data that becomes an `unresolved` fact with a closed reason (`not_found`, `wildcard_import`, `dynamic_attr`, `eval`, `dynamic_import`, `ambiguous`, `no_pack`, `not_converged`).

| Stage | Input → output | Scope |
|---|---|---|
| `discover` | repo root → files with module names | the only file walker |
| `parse` | source → ruff AST plus syntax-error diagnostics | per file; always `parse_unchecked` |
| `index` | AST → top-level definitions, imports as qualified names, module-level bindings with initializers | per file |
| `resolve` | all indexes plus pack type rows → definitions or externals, binding types, import graph | the only cross-file stage; a bounded fixpoint over immutable inputs that reports non-convergence |
| `flow` | one function → obligations with labeled edges | per function |
| `facts` | resolved view plus packs → calls, effects, state writes, entry points | small emitters |
| `compose` | `docker compose config` JSON → services, replicas, env | separate input |

Typed IDs in arenas (ruff's `IndexVec` and `newtype_index`, [cfg/graph.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/cfg/graph.rs)) suit the internals of `resolve` and `flow` without lifetimes. ruff's habit of building the semantic model and running rules in one traversal is the thing not to copy: Mental has no rules to run during the walk, so it can build first and query afterwards, and each stage stays testable alone.

Obligations need a fixed table of branch forms, not a full CFG; ruff's own `build_cfg` has empty arms for `if`, `while`, `for`, `match`, `try` and `with` ([graph.rs L203-256](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/cfg/graph.rs#L203)), which shows how missing arms hide. CodeQL's extractor is the reference: edges are `NORMAL`, `TRUE`, `FALSE`, `EXCEPTION` and `EXHAUSTED`; every call gets an exception edge, but attribute, name, subscript and iteration get one only when lexically inside a `try` ([flow.py L41, L1283-1350](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/extractor/semmle/python/passes/flow.py#L1283)). Mental can be more economical still: exception edges from explicit `raise`, from calls inside a `try` toward each handler whose type resolves, and from pack `raises` rows, with no per-call edges outside a `try`. Classifying every `Stmt` and `Expr` variant in an exhaustive `match` with `wildcard_enum_match_arm` denied makes a new ruff node kind a compile error rather than a silent gap.

### Packs reuse CodeQL's row format, but Mental writes the content

CodeQL's models-as-data are rows of `(type, access path, kind)` with a closed token grammar (`Member[x]`, `Argument[n]`, `ReturnValue`, `Instance`, `Subclass`, …) and "type rows" that say how instances arise ([ApiGraphModels.qll](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/frameworks/data/internal/ApiGraphModels.qll)), with one commented line per row in YAML pack files ([Asyncpg.model.yml](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/frameworks/Asyncpg.model.yml)). It also separates "what kind of effect" from "which library" with generic concepts such as `SqlExecution` and `Http::Client::Request` ([Concepts.qll](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/Concepts.qll#L85)). Two limits matter. CodeQL still writes FastAPI routes as QL code ([FastApi.qll L102-135](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/frameworks/FastApi.qll#L102)), and at this commit it has **no models at all** for Celery, boto3, click or Redis ([frameworks/](https://github.com/github/codeql/tree/20ed6480fa1d8c44c99368be99dda541082dc968/python/ql/lib/semmle/python/frameworks)). So Mental takes the format and writes the content, adding two tokens CodeQL lacks: `Decorates` (the function a decorator applies to, for slots such as `@app.post` and bare `@celery.task`) and `WithArg[i=literal]` (for `boto3.client("s3")`). Row kinds are `type`, `effect`, `slot`, `raises` and `config` (for assignments such as `celery.conf.task_acks_late = True`); an unknown token or kind fails pack loading. Effect kinds are generic (`db.read`, `db.write`, `tx.end`, `send:<channel>`, `http`, `file.*`, `clock`, `env`). ruff writes its FastAPI knowledge as Rust predicates ([fastapi/rules/mod.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_linter/src/rules/fastapi/rules/mod.rs#L14)); a CI grep for library names in `crates/extract/src` keeps Mental from doing the same.

Three extract rules give the most protection per line of enforcement: the exhaustive match on AST variants, the library-name grep, and a **conservation oracle** that independently counts call expressions, decorators and branch statements with a 30-line visitor and requires each to appear in the output exactly once, resolved or not. The oracle has no precedent in the studied tools; it is the direct mechanical form of P7's "extractors own completeness". Output is deterministic: facts sorted by `(file, offset, kind)`, and every fact carries an anchor whose range slices to non-empty source text.

## `mentalc`: a straight driver around a content-addressed answer store

### LLM phases split into pure planning and pure applying

None of the studied pipelines has an external oracle like an LLM inside it, so this part is derived from the pure-core pattern. Each LLM phase becomes two pure functions, `plan(inputs) -> Vec<Task>` and `apply(inputs, &Answers) -> (Output, Vec<Diagnostic>)`, and the driver sits between them: for each task it computes the key, looks in the cache and, on a miss, asks the backend. Bottom-up compilation iterates this level by level along the call graph. Everything except the driver loop stays snapshot-testable with canned answers.

The pull backend decides the core's shape. With `agent`, mentalc is called (`task next`, `task submit`) instead of calling out, so `Backend::answer(task)` cannot be the central abstraction. The LLM-loop study proposes `next_task() -> Option<Task>` and `accept(task_id, raw) -> Verdict` with `Verdict = Accepted | Repair(Task) | Failed`, all checking, caching and ledger writes inside `accept`, so every backend is judged by the same code as [spec §6.5](../../specification.md#93-llm-backends) requires. The push backends (`api`, `local`, `agent-cli`) become a loop over those two calls with one synchronous method, `fn complete(&self, &RenderedTask) -> Result<RawAnswer, BackendError>`. The architecture study adds the simplest way to hold state between calls: rust-analyzer's server is "stateless, a-la HTTP" ([architecture.md L241-245](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/docs/book/src/contributing/architecture.md#L241)), and with a content-addressed cache `task next` can rerun the cheap non-LLM phases from scratch until the first miss. The only build state on disk is then the cache, the ledger and repair counts keyed by task hash, with no session file that can drift and nothing to recover after a crash. The two studies agree on the API; this report recommends the stateless variant as the implementation behind it. Whether rerunning extract on every `task next` stays fast on repositories larger than report-jobs is unmeasured; per-file caching of extract results by content hash is the next step if not.

### Salsa solves a different problem than a batch compiler with paid, nondeterministic steps

Salsa assumes "`your_program` is a purely deterministic function of its inputs" ([how_salsa_works.md](https://github.com/salsa-rs/salsa/blob/52b12a418909c9d982a842691c6eaacfc6d62936/book/src/how_salsa_works.md)), keeps its memo tables in a long-running process, is 27,719 lines with more than a dozen required dependencies, and calls its persistence an "Initial persistent caching prototype" ([Cargo.toml L20-71](https://github.com/salsa-rs/salsa/blob/52b12a418909c9d982a842691c6eaacfc6d62936/Cargo.toml#L20); [CHANGELOG L297-306](https://github.com/salsa-rs/salsa/blob/52b12a418909c9d982a842691c6eaacfc6d62936/CHANGELOG.md#L297)). Every Mental command is a short process, the costly steps are about 15 LLM calls for a first build of report-jobs and 3 after a one-line fix ([spec §11.5](../../specification.md#143-what-to-measure-along-the-way)), and LLM answers are not deterministic: the stored answer *is* the fact. Astral itself keeps the batch linter ruff on a small file cache while the long-running type checker ty uses Salsa ([ruff cache.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff/src/cache.rs)). The right store is about 100 to 200 hand-written lines: one file per validated answer at `.mental/cache/<k[0..2]>/<k>.json`, written by temp file and rename as ruff does "to protect against data loss if the process is killed" ([cache.rs L157-199](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff/src/cache.rs#L157)). Because callee summaries enter a caller's key by content, an unchanged recompiled summary stops recompilation above it; that is the early cutoff Salsa's backdating and ninja's `restat` provide ([ninja graph.cc L225-262](https://github.com/ninja-build/ninja/blob/1a8fee23135e57cda12d47aedb19f795353fa13c/src/graph.cc#L225)), for free.

The key is `blake3` over canonical JSON of the role, the template name, the template's **content hash**, the answer schema's hash and the sorted hashes of the exact input slices. Keying on the template hash rather than the declared version means a forgotten version bump cannot serve stale answers; keying on slice hashes means an edit elsewhere in the same file invalidates nothing; the LLM's identity stays out, as [spec §6.6](../../specification.md#94-ledger-and-cache) requires. ruff warns that `std::hash::Hash` "may not be portable" ([cache_key.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_cache/src/cache_key.rs#L1)), and Mental's keys appear in the ledger and may be shared later, so they must use a cryptographic hash of canonical bytes. Prompts are Markdown files embedded with `include_str!`, as Codex does ([compact.rs](https://github.com/openai/codex/blob/e9919f4b4ef9aa4b15af92589c7f44581d1ad26a/codex-rs/prompts/src/compact.rs)), with a checked-in `prompts.lock` of `(version, sha256)` that a test compares, so the version in the ledger cannot lie. Checks run again on every cache hit rather than entering the key: they are cheap and deterministic, and a stricter check then turns exactly the answers that now fail into repairs. ruff caches only clean results ([diagnostics.rs L365](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff/src/diagnostics.rs#L365)) and Mental should too, but ruff's leniency on loss, treating a corrupt file as empty and evicting after 30 days ([cache.rs L100-247](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff/src/cache.rs#L100)), does not transfer: a Mental entry is a paid judgment that defines the model. Corrupt entries are reported, nothing expires by time, and in `mentalc check` or an offline build a miss is a hard error. Every miss should be explained, as `ninja -d explain` does, by naming the input hash that changed, so the spec's "a one-line fix recompiles exactly these units" becomes a test.

### A synchronous backend, a small HTTP client, and schemas inside the provider's subset

Nothing in the loop needs async. Fifteen calls per build do not need concurrency, and the only Rust MCP SDK makes tokio mandatory. A blocking `ureq` client resolves to 33 crates with rustls (16 without TLS), while clust, the closest small Anthropic client, is 8,550 lines on async `reqwest`, hard-codes a 2024 model enum and was last updated in March 2025 ([clust claude_model.rs](https://github.com/mochi-neko/clust/blob/81fda7c644a6e01971c378e53f4d0afdb873a9b9/src/messages/claude_model.rs)); Anthropic publishes no official Rust SDK. Codex's retry logic (retry 429, 5xx and transport errors, exponential backoff with jitter, honor `Retry-After`, a maximum attempt count) is about 100 lines ([codex retry.rs](https://github.com/openai/codex/blob/e9919f4b4ef9aa4b15af92589c7f44581d1ad26a/codex-rs/codex-client/src/retry.rs)). The Anthropic API reference read by the LLM-loop study (the copy bundled with Claude Code; public counterpart at [platform.claude.com/docs](https://platform.claude.com/docs)) sets three constraints: structured outputs reject recursive schemas and numeric or length constraints and require `additionalProperties: false` on every object; `stop_reason` of `refusal` or `max_tokens` voids the schema guarantee, so those are backend errors, not repair triggers; and on API version `2026-10-21` sampling parameters such as `temperature` return a 400, so determinism in tests can only come from recorded answers.

Answer types are Rust structs with `deny_unknown_fields`, so deserialization is the structural validator. The schema sent to the LLM is derived from the same types with schemars, which emits `additionalProperties: false` only under `deny_unknown_fields` and `oneOf` for tagged enums ([schema_exprs.rs](https://github.com/GREsau/schemars/blob/4791bb7352555d339e45658ca09c092ed9fa1f5d/schemars_derive/src/schema_exprs.rs)); one `Transform` rejects anything outside the provider subset and rewrites `oneOf` to `anyOf`. A JSON Schema validator crate would add 64 crates for what serde already does. Constraints the schema cannot express, including the guard grammar, become mentalc checks.

Repair follows Aider, whose message quotes each failed block verbatim, offers "Did you mean to match some of these actual lines", and says which blocks passed ([editblock_coder.py L41-123](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/coders/editblock_coder.py#L41-L123)), with a cap of 3 rounds ([base_coder.py L932-944](https://github.com/Aider-AI/aider/blob/5dc9490bb35f9729ef2c95d00a19ccd30c26339c/aider/coders/base_coder.py#L932-L944)), the same as SysMoBench's correction loop ([method.py](https://github.com/specula-org/SysMoBench/blob/827899e489fb382b5a37c3c55a5ceb7bf38372c9/tla_eval/methods/direct_call/method.py)). A Mental repair is a `repair` task carrying the original inputs, the previous answer and a structured list of failures (check, record ID, rule, evidence such as an anchor quote and the closest real lines). It asks for the whole answer again rather than a patch, because coverage and guard algebra are global over the answer; nobody has measured which works better. Specula's stop gate is the counterexample for the limit: it is explicitly fail-open on internal errors ([stop_gate.py L41-45](https://github.com/specula-org/Specula/blob/1a86e7e5ca7ff8567dbdadd39bbe2d953c63ed65/src/specula/stop_gate.py)). In Mental, exhausting repairs fails the build with every failure attached. Every call, including failed and repair calls, appends one complete JSON line to `calls.jsonl` before its records are used, with raw answers stored by content hash beside it; Codex's rollout JSONL and Aider's `--llm-history-file` are the precedents for an append-only log, though neither records per-call provenance as Mental's ledger does.

### The MCP server is a few hundred synchronous lines, not an SDK

rmcp is 59,664 lines plus 1,841 in macros, its tokio dependency is not optional, the minimal stdio server resolves to **61 crates** against 14 for serde, serde_json and thiserror, and it shipped majors 1.0, 2.0 and 3.0 between March and July 2026 ([rmcp Cargo.toml](https://github.com/modelcontextprotocol/rust-sdk/blob/c644b75aafa0a437e5d814b5672d82ed6b4899ca/crates/rmcp/Cargo.toml); [CHANGELOG](https://github.com/modelcontextprotocol/rust-sdk/blob/c644b75aafa0a437e5d814b5672d82ed6b4899ca/crates/rmcp/CHANGELOG.md)). The stdio transport is one JSON message per line, stdout for protocol only, exit on EOF ([stdio.mdx](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/0175d20f8b2c49e0402c37c37ed39ae2be47277e/docs/specification/2026-07-28/basic/transports/stdio.mdx)). The real risk of writing it by hand is spec churn: revision 2026-07-28 removed `initialize` and `ping`, requires `server/discover`, and adds `resultType`, `ttlMs` and `cacheScope` ([changelog.mdx](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/0175d20f8b2c49e0402c37c37ed39ae2be47277e/docs/specification/2026-07-28/changelog.mdx)), while a server may serve legacy clients by answering `initialize` too ([versioning.mdx L126-171](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/0175d20f8b2c49e0402c37c37ed39ae2be47277e/docs/specification/2026-07-28/basic/versioning.mdx)). A dual-era server over `BufRead`/`Write` is estimated at 250 to 400 lines; that figure is an estimate, not a measurement. Processing is sequential, so a cancellation can only arrive after its response was written, which satisfies the spec trivially.

The spec's tool rules shape the surface: `tools/list` "MUST NOT vary per-connection or as a side effect of other requests", state goes in "explicit, server-minted handles", and validation and business errors return `isError: true` so that clients feed them back to the model ([tools.mdx L60-66, L690-785](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/0175d20f8b2c49e0402c37c37ed39ae2be47277e/docs/specification/2026-07-28/server/tools.mdx)). So the tool list is fixed: `mental_task_next` returns the task, its `task_id` and its answer schema inside the result; `mental_task_submit(task_id, answer)` returns `isError: true` with the repair text on a failed check or a stale handle. SysMoBench keeps its attempt counter in server memory ([server.py](https://github.com/specula-org/SysMoBench/blob/827899e489fb382b5a37c3c55a5ceb7bf38372c9/tools/submit_spec/src/submit_spec/server.py)), which a restart loses; Mental's on-disk state is exactly what the stateless revision asks for. CLI and MCP share one core function per operation, so their own tests only cover the mapping.

### Diagnostics render two ways, and exit codes have three levels

ruff exits 0 on success, 1 when it "ran, found lint errors" and 2 when "linting failed"; its `main.rs` only parses arguments, calls `run`, exits quietly on a broken pipe and otherwise prints the error chain to stderr ([ruff lib.rs L37-56](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff/src/lib.rs#L37); [main.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff/src/main.rs)). ruff also ships twelve renderers ([render/](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_db/src/diagnostic/render)); Mental needs a human one and `--json`, which emits the model's own `Diagnostic` so there is no second schema. For `mentalc`: 0 for a complete model with no error diagnostics, 1 for a command that ran but found problems (errors from `check`, repairs exhausted), 2 for mentalc's own failure (I/O, config, unreachable backend, cache miss offline, bad usage). Exit codes are part of the CLI contract and are snapshot-tested.

## `mentalvm`: Stateright's interface, P's schedules, and no reduction yet

### Pure step functions over value-typed configurations

Stateright's whole model interface is three methods, `init_states`, `actions` and `next_state`, and every checker is written against them alone ([lib.rs L158-179](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/lib.rs#L158-L179)); its actor layer turns delivery, drops, timeouts, crashes and random selection into one action enum, which maps onto Mental's `sched`, `env`, `data` and `pick` ([actor/model.rs L46-66](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/actor/model.rs#L46-L66)). Shuttle's `Scheduler` is the right shape for strategies: one method per decision and `None` to end ([scheduler/mod.rs L75-100](https://github.com/awslabs/shuttle/blob/72bdbdb612c2311905c84bbc73d59f12a5b17e43/shuttle-engine/src/scheduler/mod.rs#L75-L100)). P shows the cost of splitting the choice point: separate operation, boolean and integer choice methods force its DFS to keep three parallel stacks ([DFSStrategy.cs](https://github.com/p-org/P/blob/260da928f67569ca7a8c0039a02d0bad7cde6096/Src/PChecker/CheckerCore/SystematicTesting/Strategies/Exhaustive/DFSStrategy.cs)). The merged design is pure free functions, `initial`, `enabled` (sorted, deduplicated) and `fire(&Model, &Config, &Choice) -> Fired`, where `Fired` is either the next configuration plus one step, or an `Outcome` plus the last step. One `Chooser` trait picks from the enabled list and drives `run`; `explore` owns its own DFS stack; `replay` returns a verdict per choice. Model gap, deadlock, illegal write, zero-time cycle and invariant violation come back as data. Shuttle and P detect failures through panics because they run real code; Mental runs a model and has no such excuse.

Two Stateright details are warnings. Its actor model returns `None` for no-op deliveries, with the code's own caveat that this is "only safe if invariants do not relate to the existence of envelopes on the network" ([model.rs L418-440](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/actor/model.rs#L418-L440)), and PEx returns only the creating machine whenever one exists ([ExplicitSearchScheduler.java L552-568](https://github.com/p-org/P/blob/260da928f67569ca7a8c0039a02d0bad7cde6096/Src/PEx/src/main/java/pex/runtime/scheduler/explicit/ExplicitSearchScheduler.java#L552-L568)). Both hide a reduction inside the semantics. Mental keeps `enabled` complete and puts all pruning in strategies, where a test can switch it off.

None of the checkers uses undo logs. Those that own their state clone on step, and Stateright makes it cheap with a `Vec<Arc<State>>` per actor and `Cow` on delivery ([model_state.rs L15-23](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/actor/model_state.rs#L15-L23)). The testers that run real code (Shuttle, loom) cannot snapshot and re-execute every path from the start, and loom fails with "Is the model fully deterministic?" when re-execution leaves the recorded path ([loom path.rs](https://github.com/tokio-rs/loom/blob/9d549cd5357a5485900f4c53951fc1726319659f/src/rt/path.rs)). Mental can snapshot, so `Config` derives `Clone, Eq, Ord, Hash, Serialize, Deserialize`, holds only `Vec`, `BTreeMap`, `BTreeSet`, `Arc` and plain values, and changes through `Arc::make_mut`. Snapshots, stepping backwards and DFS backtracking then need no extra code, and the spec's "two configurations are equal however they were reached" holds by construction ([spec §8.1](../../specification.md#121-configuration-and-steps)). No persistent-collection crate is warranted until profiling says so.

### Schedules name choices by semantic ID and store their values

Stateright records witnesses as action indices and rebuilds them by re-running the model ([path.rs L21-90](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/checker/path.rs#L21-L90)); Shuttle stores task IDs plus a seed and regenerates random values from it ([scheduler/mod.rs](https://github.com/awslabs/shuttle/blob/72bdbdb612c2311905c84bbc73d59f12a5b17e43/shuttle-engine/src/scheduler/mod.rs)). Neither survives a model change, which is what Mental's replay must handle ([spec §8.9](../../specification.md#123-strategies)). P stores values explicitly ([ScheduleStep.cs](https://github.com/p-org/P/blob/260da928f67569ca7a8c0039a02d0bad7cde6096/Src/PChecker/CheckerCore/SystematicTesting/Traces/ScheduleStep.cs)) and names its replay failures: "cannot detect id", "next step is not a scheduling choice", "execution is longer than trace" ([ReplayStrategy.cs L93-107](https://github.com/p-org/P/blob/260da928f67569ca7a8c0039a02d0bad7cde6096/Src/PChecker/CheckerCore/SystematicTesting/Strategies/Special/ReplayStrategy.cs#L93-L107)). These map onto Mental's verdicts: a choice whose ID is not enabled is `infeasible`; a kind mismatch or a schedule that runs out early or late is `diverged`; a found and applied choice is `matched`. P's optional suffix strategy, which takes over at the first mismatch, is the right shape for "replay, then keep searching" after a fix. A `Choice` is therefore an enum of `Sched(activation)`, `Env { at, act }`, `Data { at, value }` and `Pick { at, target }`, matched by equality as in Stateright's by-value `Path::from_actions` ([path.rs L92-119](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/checker/path.rs#L92-L119)).

### Determinism is built in and then tested, because every project was bitten

Stateright sorts its action list because "some iterators like `HashableHashSet` do not guarantee a stable order" ([model.rs L342-386](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/actor/model.rs#L342-L386)); its "stable" fingerprint is ahash with fixed keys and a `// TODO: how to get these?` ([lib.rs L344-390](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/lib.rs#L344-L390)), while ahash's README says different machines "will observe different hash values"; its simulation RNG is `StdRng` under `// FIXME: use a reproducible rng` ([simulation.rs L46-48](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/checker/simulation.rs#L46-L48)). PEx combines hashes with XOR, where equal elements cancel ([ComputeHash.java](https://github.com/p-org/P/blob/260da928f67569ca7a8c0039a02d0bad7cde6096/Src/PEx/src/main/java/pex/values/ComputeHash.java#L24-L52)). TLC alone uses a fixed-spec Rabin fingerprint and reports the collision probability after every run ([ModelChecker.java L962-972](https://github.com/tlaplus/tlaplus/blob/d8fb231de4e4b5d02c1b2ed1ac759c086f694021/tlatools/org.lamport.tlatools/src/tlc2/tool/ModelChecker.java#L962-L972)). Mental's answer is ordered collections only, sorted `enabled`, and an **exact** visited set of full configurations in version one, which is PEx's collision-free `Exact` mode ([StateCachingMode.java](https://github.com/p-org/P/blob/260da928f67569ca7a8c0039a02d0bad7cde6096/Src/PEx/src/main/java/pex/runtime/scheduler/explicit/StateCachingMode.java)). If fingerprints are ever needed, they hash a canonical serialization with a specified, version-pinned algorithm, keep at least 64 bits with TLC-style collision reporting, and keep exact mode as a test oracle. Sampled search uses one named PRNG (Shuttle uses `Pcg64Mcg`, [pct.rs L50](https://github.com/awslabs/shuttle/blob/72bdbdb612c2311905c84bbc73d59f12a5b17e43/shuttle-schedulers/src/pct.rs#L50); a 10-line SplitMix64 avoids the `rand` dependency) seeded from the run file; the core never reads entropy, and the CLI prints any seed it picks. The core must build for `wasm32-unknown-unknown`; Stateright, Shuttle and loom all read environment variables or wall clocks inside their checkers, which Mental's bounds and CLI replace.

### Bounded DFS with an exact visited set covers version one without partial-order reduction

Of the six checkers, only loom implements POR: a DPOR driven by vector clocks, per-object "last dependent access", a conservative "explore all threads" fallback, and an extra backtrack point because "preemption bounded DPOR requires conservatively adding another backtrack point" ([execution.rs L134-160](https://github.com/tokio-rs/loom/blob/9d549cd5357a5485900f4c53951fc1726319659f/src/rt/execution.rs#L134-L160); [path.rs L336-385](https://github.com/tokio-rs/loom/blob/9d549cd5357a5485900f4c53951fc1726319659f/src/rt/path.rs#L336-L385)). It is coupled to loom's runtime objects and to stateless re-execution, and cannot be lifted out. Stateright, Shuttle, P, PEx and TLC rely on bounds, symmetry, state caching or randomness instead, and **no project tests POR against unreduced search**. Mental's report-jobs bounds are tiny (1 request, 2 workers, 1 duplicate, 1 preemption), "activations run until they wait" already removes interleavings inside an activation, and a visited set merges independent orders that reach the same configuration. Bounded DFS with an exact visited set and a loom-style preemption bound (a `sched` choice of another activation while the current one can still step, with the non-preempting choice tried first, [execution.rs L163-200](https://github.com/tokio-rs/loom/blob/9d549cd5357a5485900f4c53951fc1726319659f/src/rt/execution.rs#L163-L200)) is complete for the stated bounds with no reduction code at all. The spec's own open question, "which step kinds may safely be reordered during search is unproven", is a second reason to wait. If POR becomes necessary, sleep sets over the same static footprints used for atomicity are the simplest form, shipped only with a differential test; how sleep sets combine with a budgeted visited set needs a design note first, and the recommendation rests on the literature, not on code read here.

One subtlety applies whatever is chosen: a configuration reached with budget left is not equivalent to the same configuration reached with the budget spent. Stateright keeps depth in the job tuple but deduplicates by state alone ([dfs.rs L31, L329](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/checker/dfs.rs#L31)), which can prune a state first reached deep; this is an inference from reading, not a tested bug. Mental's visited key must include the remaining budgets (duplicates, preemptions, depth), or the search must keep the best budget per configuration. PEx's visited set also yields cycle detection: a state seen again within the same schedule is "an infinite loop", and one seen in another schedule is pruned ([ExplicitSearchScheduler.java L249-290](https://github.com/p-org/P/blob/260da928f67569ca7a8c0039a02d0bad7cde6096/Src/PEx/src/main/java/pex/runtime/scheduler/explicit/ExplicitSearchScheduler.java#L249-L290)); with `now` in the configuration, that is Mental's zero-time cycle.

None of the checkers has a schedule shrinker. Stateright and TLC get short witnesses from BFS, Shuttle's `shrink.rs` only replays hand-minimized schedules ([shrink.rs](https://github.com/awslabs/shuttle/blob/72bdbdb612c2311905c84bbc73d59f12a5b17e43/shuttle/tests/basic/shrink.rs)), and P has none. proptest's vector shrinking is the loop to borrow: try deleting each element, then simplify each kept one, step back when a candidate stops failing, and on bail-out return the most recent failing case ([collection.rs L591-650](https://github.com/proptest-rs/proptest/blob/70cf37d46b7d83393b6ed94c611f8c52209f585d/proptest/src/collection.rs#L591-L650); [runner.rs L769-880](https://github.com/proptest-rs/proptest/blob/70cf37d46b7d83393b6ed94c611f8c52209f585d/proptest/src/test_runner/runner.rs#L769-L880)). Mental's minimizer, about 40 lines, starts from a witness found with fewest preemptions first and repeatedly deletes one choice, re-checking each candidate by replay with skipped choices falling back to the non-preempting default, keeping it when the same outcome kind occurs at the same node. Version one needs concrete runs, bounded-exhaustive DFS, replay and the minimizer; sampled search is about 30 lines on top. Stateright's web explorer and thread pool, Shuttle's PCT and wrapper crates, loom's weak-memory model, P's roughly 3,770 lines of strategies, and TLC's disk and distributed modes are where those codebases grew.

## Testing: every clever algorithm gets a dumb twin

### Tests are input text and expected output through one helper

rust-analyzer's tests "are data driven and do not test the API": one `#[track_caller] fn check(input, expect)` per feature is "the single place that actually exercises a particular API", followed by "a hundred more tests that don't care about the specific API at all" ([architecture.md L416-436](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/docs/book/src/contributing/architecture.md#L416)). jaq gets one test per line from a `yields!` macro ([tests.rs](https://github.com/01mf02/jaq/blob/c6cc7d3721ccfb212f153006c4fc90c56567540c/jaq-core/tests/tests.rs#L1)). rust-analyzer's multi-file fixture strings (`//- /main.rs crate:a deps:b`, [fixture.rs](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/crates/test-utils/src/fixture.rs#L1)) and its "minimal tests" rule keep fixtures readable, and its tests use no libstd so they stay fast ([architecture.md L412-414](https://github.com/rust-lang/rust-analyzer/blob/114dcb8d6f50aca1ef14d67b831a7560362f8f69/docs/book/src/contributing/architecture.md#testing)). ruff's harness checks invariants on every fixture for free, panicking when fixes fail to converge or leave a syntax error ([test.rs L244-360](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_linter/src/test.rs#L244-L360)). Mental's shared helpers should do the same: every fixture model gets its IDs checked for uniqueness and order, its references resolved, its anchors' quotes found and its output checked for idempotence, so individual tests stay one line.

| Layer | Where | What |
|---|---|---|
| Unit | `src/<module>/tests.rs` | one behavior per test through a module-local `check` helper, inline snapshots |
| Crate API | `<crate>/tests/` | public behavior; directory walks over `tests/data/{ok,err}/`, where `ok` asserts no diagnostics and `err` at least one |
| Property and differential | `tests.rs` or `tests/props.rs` | round trips, canonical forms, oracle agreement |
| CLI and MCP | `mentalc/tests/` | a handful of heavy tests on a temp copy of a fixture tree; MCP transcripts through `serve(reader, writer)` |
| Acceptance | `mentalc/tests/report_jobs.rs` | the whole pipeline on report-jobs, replayed from recorded answers, in debug and release |
| Tidy | one `tests/tidy.rs` | the source-level rules from the first section |
| Fuzz | `fuzz/` (its own workspace) | readers only; crashes come back as fixtures |

### Source fixtures carry their expectations inline

For `extract`, the best test format comes from tools that annotate fixtures with what must be produced. CodeQL's `.expected` file "should always be empty": expectations are comments (`$ tag=value`), and known gaps are marked `MISSING:` or `SPURIOUS:` so that fixing one is reported ([InlineExpectationsTest.qll](https://github.com/github/codeql/blob/20ed6480fa1d8c44c99368be99dda541082dc968/shared/util/codeql/util/test/InlineExpectationsTest.qll)); 41 framework fixtures carry `MISSING:` markers. stack-graphs packs several files into one with `# --- path: one.py ---` headers and places assertions under a caret, with the whole syntax defined by four regexes ([test.rs L14-96](https://github.com/github/stack-graphs/blob/fcb7705d5b38ae13b3665a9b2c882e5a97243d44/tree-sitter-stack-graphs/src/test.rs#L14)). Kythe does the same with `//-` lines ([structinit.go](https://github.com/kythe/kythe/blob/69141f022689a611e8a4a1d9b08a3783a2e8a9ed/kythe/go/indexer/testdata/structinit.go)). PyCG supplies the categories: 18 of them, each case a `main.py`, an expected `callgraph.json` and a one-line README ([micro-benchmark/snippets](https://github.com/vitsalis/PyCG/tree/8d5dc40837803beef1d8d379fbf2cdad6cd94641/micro-benchmark/snippets)). ty's Markdown mdtest is elegant but needs a 1,882-line harness ([ty_test README](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ty_test/README.md)), which is bloat here. Mental's harness, about 200 lines, discovers `.py` fixtures by category with `insta::glob!`, reads `# $ effect=db.write` or caret lines, fails on any unmatched expectation or unexpected fact for a tag in use, and treats "fixed MISSING" as a failure so the marker gets removed. Report-jobs itself is not edited; an annotated fragment copy carries the expectations, and a drift test strips the annotations and compares the result with `examples/report-jobs`. Per-function obligations are snapshotted as compact text (`L22 if … → [true: raise HTTPException(400)] [false: …]`), the same idea as ruff's Mermaid CFG snapshots ([cfg/mod.rs](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff_python_semantic/src/cfg/mod.rs)).

For `model`, cargo-platform's helpers are the template: `good(s, expected)`, `good_canon(s, canon, expected)` and `bad(s, exact_message)`, each run through both `FromStr` and serde so the two cannot diverge ([test_cfg.rs L49-96](https://github.com/rust-lang/cargo/blob/382ecb8707b82592bb7176ba62b07590c29dee35/crates/cargo-platform/tests/test_cfg.rs#L49-L96)). A completeness test iterates a `const ALL: &[Code]` kept honest by an exhaustive `match` and requires a fixture that triggers each diagnostic code, which is milestone 1's "rejects seeded errors" made mechanical ([spec §11.4](../../specification.md#142-milestones)). A small hand-built model covering every record kind is snapshotted as a format freeze, so any byte change in the format is a reviewed diff.

For `mentalvm`, the model checkers' self-tests transfer directly. P's regression suite has `Correct`, `DynamicError` and `StaticError` folders per feature, with 145 known-bug programs ([RegressionTests](https://github.com/p-org/P/tree/260da928f67569ca7a8c0039a02d0bad7cde6096/Tst/RegressionTests)); TLC asserts exact generated, distinct and left counts in 282 test files ([EvalExceptionLivenessTest.java L50-51](https://github.com/tlaplus/tlaplus/blob/d8fb231de4e4b5d02c1b2ed1ac759c086f694021/tlatools/org.lamport.tlatools/test/tlc2/tool/EvalExceptionLivenessTest.java#L50-L51)); Stateright pins `unique_state_count()` per checker and per reduction (2pc: 8,832 states plain, 665 with symmetry, same verdicts, [2pc.rs L183-198](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/examples/2pc.rs#L183-L198)) and validates expected witnesses by replay with `assert_discovery`, so a legitimate change of search order is not a false failure ([checker.rs L534-560](https://github.com/stateright/stateright/blob/ab8c8be9341505e0f71edbe5dd88ed275bd976a4/src/checker.rs#L534-L560)). loom asserts exact outcome sets in litmus tests ([tests/spec.rs](https://github.com/tokio-rs/loom/blob/9d549cd5357a5485900f4c53951fc1726319659f/tests/spec.rs)). Shuttle's replay round-trip tests are all `#[ignore]`d today because "replay mechanism is broken" ([replay.rs L32-51](https://github.com/awslabs/shuttle/blob/72bdbdb612c2311905c84bbc73d59f12a5b17e43/shuttle/tests/basic/replay.rs#L32-L51)), which is the reason Mental's round trip (explore, serialize the run file, parse, replay, same outcome, all `matched`) must gate CI. The corpus follows P's layout (`tests/corpus/{bug,correct}/<name>/`) with one bug model per outcome kind, report-jobs before and after the fix, and an insta snapshot of each outcome, minimal witness and state counts. One scenario test per step rule of [spec §8.2](../../specification.md#121-configuration-and-steps) completes it.

### Differential oracles, fault sweeps and mutants check behavior, not just execution

Each clever algorithm keeps a reference of about 30 lines inside its test module, never shipped and never mutated. wasmtime runs the same generated module on two engines and requires equal results and matching errors ([oracles.rs L460-604](https://github.com/bytecodealliance/wasmtime/blob/c52bc6d8fc7ebf2ba3f7e39ab3203a3c13c1d272/crates/fuzzing/src/oracles.rs#L460-L604)); both BDD crates test against truth tables, biodivine with "a predefined set of randomness seeds" and boolean_expression with an unseeded `thread_rng()` that makes failures unreproducible ([biodivine fuzzing](https://github.com/sybila/biodivine-lib-bdd/blob/f2c39b81630d4fd1e3e51245c0dfebf11855811e/src/_test_bdd/_test_bdd_logic_fuzzing.rs#L1-L18); [bdd.rs L755-800](https://github.com/cfallin/boolean_expression/blob/795b89567e05f54907b89453bdd481d0b01f0c93/src/bdd.rs#L755-L800)); TigerBeetle's `exhaustigen` enumerates every input of a small bounded space instead of sampling ([exhaustigen.zig](https://github.com/tigerbeetle/tigerbeetle/blob/a2a3c7064519e08233abe26c54a43fca2f9ad9bc/src/testing/exhaustigen.zig)). For Mental: the guard checker against plain enumeration, exhaustively for every guard set over three atoms and by proptest beyond, with witnesses checked (a reported gap satisfies no guard, an overlap at least two); `explore` against a naive recursive DFS with no caching on tiny generated models, requiring the same verdict set and a replayable schedule for every violation; and the minimizer checked for 1-minimality. Round-trip properties cover every reader: `read(write(m)) == m`, `write(read(b)) == b` on goldens, and for arbitrary strings, "accepted implies re-displays identically", which catches SCIP's class of bug. toml_edit's fuzz oracle is the model for the readers that face outside bytes (JSONL, guards, LLM answers, MCP lines, run files): parse, print, re-parse, and require the printed text to be stable ([parse_document.rs](https://github.com/toml-rs/toml/blob/563cb1a5d133e39d1008d4d4148ef35d3bba379f/crates/toml_edit_fuzz/parse_document.rs)). proptest regression files are committed, as its book recommends ([failure-persistence.md](https://github.com/proptest-rs/proptest/blob/70cf37d46b7d83393b6ed94c611f8c52209f585d/book/src/proptest/failure-persistence.md)).

Faults are injected at seams the product already has. SQLite fails the N-th allocation or I/O call, raises N until the operation succeeds, runs each sweep in transient and persistent modes, and checks integrity afterwards ([SQLite testing](https://www.sqlite.org/testing.html); [test_malloc.c L65-86](https://github.com/sqlite/sqlite/blob/33fd659df2a4d2f07071ec61b329b4aa6a7377d5/src/test_malloc.c#L65-L86)); wasmtime ports the method to Rust with a counting dry run and a post-check that "nothing was left half-registered" ([oom.rs](https://github.com/bytecodealliance/wasmtime/blob/c52bc6d8fc7ebf2ba3f7e39ab3203a3c13c1d272/crates/fuzzing/src/oom.rs)). Mental's seam is the backend trait: a `Replay` backend serving recorded answers by cache key and failing loudly on a miss, hand-written bad answers for every check kind (Specula's switch files as data, [single_session_adapter.py](https://github.com/specula-org/Specula/blob/1a86e7e5ca7ff8567dbdadd39bbe2d953c63ed65/tests/e2e/fixtures/single_session_adapter.py)), and a `Countdown<B>` wrapper swept over every call in both modes, after which the cache and ledger must be consistent and a clean rerun must produce a byte-identical model. The pull protocol gets a proptest over operation sequences (`Next`, `Submit(valid|invalid)`, `SubmitStale`, `SubmitTwice`, `Reopen`, `CrashMidWrite`) whose invariants are that the final model equals an uninterrupted run's, repairs never exceed the cap, and stale or duplicate submits change nothing. File I/O needs no `Fs` trait: pure readers and writers plus real temp directories for the few error paths. No mocking crates; a 20-line scripted backend is easier to read. Codex tests the requests it sends with insta snapshots after normalizing volatile values ([normalize.rs](https://github.com/openai/codex/blob/e9919f4b4ef9aa4b15af92589c7f44581d1ad26a/codex-rs/core/tests/common/context_snapshot/normalize.rs)); Mental snapshots rendered tasks for report-jobs the same way, so a diff in a golden task is exactly the signal that a cache key changed.

Mutation testing runs on the diff: `cargo mutants --in-diff git.diff --in-place --profile mutants -- --all-targets`, failing on any missed mutant, with a `mutants` profile without debug info ([performance.md](https://github.com/sourcefrog/cargo-mutants/blob/6c720ae82a1784b84cfa06066f7b0d59ed1798d0/book/src/performance.md)) and every skip visible as `#[mutants::skip]` with a reason ([skip.md](https://github.com/sourcefrog/cargo-mutants/blob/6c720ae82a1784b84cfa06066f7b0d59ed1798d0/book/src/skip.md)). The docs warn that "a diff that only deletes or changes test code won't cause any mutants to run" ([in-diff.md](https://github.com/sourcefrog/cargo-mutants/blob/6c720ae82a1784b84cfa06066f7b0d59ed1798d0/book/src/in-diff.md)), so an occasional full run is worth adding once the suite is fast. Because cargo-mutants already turns `<` into `==`, `>` and `<=` ([visit.rs L802-808](https://github.com/sourcefrog/cargo-mutants/blob/6c720ae82a1784b84cfa06066f7b0d59ed1798d0/src/visit.rs#L802-L808)), SQLite's `testcase()` boundary macros are unnecessary: a missing limit test shows up as a missed mutant. Two practices turn mutants that would otherwise be skipped into failures. Every loop gets a hard cap that returns a "bound exceeded" outcome (TigerBeetle's "put a limit on everything", [TIGER_STYLE.md](https://github.com/tigerbeetle/tigerbeetle/blob/a2a3c7064519e08233abe26c54a43fca2f9ad9bc/docs/TIGER_STYLE.md)), so a mutated search loop fails fast instead of hanging. Speed-only code, such as the visited set or later POR, is made observable by pinning exact state counts on tiny models. Coverage gates at 100% of the diff with `cargo llvm-cov --branch`, which requires nightly ([cargo-llvm-cov](https://github.com/taiki-e/cargo-llvm-cov)). Coverage marks (`cov_mark`) add little on top of mutants plus branch coverage and are optional. SQLite's last rule also transfers: test what ships, so the acceptance test runs in release and the `mentalvm` replay tests run on the WebAssembly target.

Determinism and speed hold the suite together. Tests never read the clock, the network or a real LLM; CI has no API key, and a missing key must fail with a clear error, which a test asserts. cargo-mutants needs a tree "where `cargo test` passes reliably when copied to a temporary directory" ([using-results.md](https://github.com/sourcefrog/cargo-mutants/blob/6c720ae82a1784b84cfa06066f7b0d59ed1798d0/book/src/using-results.md)), and its cost is mutants times suite time, so the proposed budget is a workspace suite under about 15 seconds, no test over one second (nextest `slow-timeout`), heavy tests gated locally but always run in CI, and the acceptance test under five seconds. These numbers are proposals to calibrate once the crates exist.

## Settled between studies

The testing study recommended expect-test as the only snapshot tool; the architecture and record-format studies recommended insta. This is settled in favor of **insta**. Small outputs use inline snapshots (`insta::assert_snapshot!(value, @"…")`), which give expect-test's ergonomics without a second tool, and large outputs (sorted JSONL, rendered diagnostics, traces one step per line) use file snapshots. CLI output is tested with **insta_cmd**, recording success, exit code, stdout and stderr, with filters for temp paths and the mentalc version, as ruff's `CliTest` does ([ruff tests/cli/lint.rs L10-44](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/crates/ruff/tests/cli/lint.rs#L10)). CI runs with `INSTA_UPDATE=no` and rejects unreferenced snapshots, as ruff's `cargo insta test --unreferenced reject` does ([ruff ci.yaml L475](https://github.com/astral-sh/ruff/blob/b140af2f48bddf33a1ae984174af3180236aaaaf/.github/workflows/ci.yaml)). Only human-readable renderings are snapshotted, never `Debug` output of internal structs. Whether `insta_cmd`'s version tracks the chosen `insta` was not checked.

The **report-jobs reference model is a hand-written golden** ([spec §11.4](../../specification.md#142-milestones)): the specification of what a build must produce, not an observation of what it did. It is compared with a plain assertion and a readable diff and is never rewritten by snapshot tooling; a tidy test fails if any snapshot path points into `examples/`. Snapshots of the replayed build output sit beside it as regression guards. When prompts change, the recorded answers miss by design, and re-recording is an explicit, reviewed step that needs an LLM key and fails without one.

## Open questions

- **Coverage mechanics.** It is unverified whether rustc's branch coverage counts the panic side of `assert!`/`debug_assert!` or `?` desugaring as branches, and no tool for *diff* branch coverage was confirmed; cargo-llvm-cov's lcov output reaches Codecov as lines only. A 20-line spike should settle both before the 100% gate and the assertion rule are fixed together.
- **Provider and client details.** Whether Anthropic's strict structured outputs accept optional properties (which decides whether answer structs may hold `Option<T>`) and whether they accept `oneOf` is not stated in the reference read. Which MCP revision Claude Code and Codex send in November 2026, and whether the official conformance suite can drive a stdio server, were not checked.
- **Measurements not taken.** Compile time of ruff's crates against tree-sitter; how often ruff bumps break compilation in practice; the true line counts of the hand-written MCP server and Messages client; search speed and state counts on report-jobs; whether `task next` rerunning extract stays fast on larger repositories.
- **Design notes needed before code.** How sleep sets combine with a budgeted visited set, if POR is ever added; the domain-constraint rule for dependent predicates; the definition of a call-graph edge; which fields of the hand-written reference model must match a replayed build exactly, given that display names come from the LLM.
- **No precedent.** The plan/apply split around an LLM, a cache keyed on prompt content, record and replay of LLM answers as test fixtures, the conservation oracle for `extract`, and property tests of a pull protocol were all derived for Mental. None of the studied projects documents a mutation-testing or diff-coverage gate either, so there is no outside evidence of their yield on code like Mental's.

## Conclusion

The research changes the question from "which libraries should Mental build on" to "which seams should Mental own". Every large dependency examined (Salsa, rmcp, stack-graphs, ty, a JSON Schema validator, a BDD library) solves a harder problem than Mental has, and in each case the part Mental needs is a few hundred lines of plain code behind a seam it already must define: the record format, the backend trait, the `Choice` enum, the cache key. The one dependency worth its cost is ruff's parser, and it is worth it only if its types never leave `extract`. Owning the seams is also what makes exhaustive testing affordable, because each seam is where a recorded answer, a countdown fault, a reference oracle or a replayed schedule plugs in without a single test-only branch in production code.

The sharpest lesson is about honesty, not size. The studied codebases most often failed silently: PyCG dropped calls it could not resolve, boolean_expression read a missing variable as false, Stateright's fingerprints changed by machine, Shuttle's replay tests rotted behind `#[ignore]`, Specula's gate failed open. Mental's design already says "fail rather than degrade" and "never guess"; these studies show that the way to keep that promise in code is to make every unknown a named value (an `unresolved` reason, an `infeasible` verdict, a `guard-check-too-large` diagnostic, a "bound exceeded" result) and to test that each one is produced.
