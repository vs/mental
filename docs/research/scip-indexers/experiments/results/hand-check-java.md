# Part J: answers read by hand

The plan asked for 30 paired sites per site kind and project, checked in an IDE. This check is
smaller: 3 sites drawn at random (fixed seed 42) from the global answers of each project and
site kind, 63 in all, each read against its source line and the file it points into.

| Project | Read | Right | Wrong |
|---|---|---|---|
| spring-petclinic | 21 | 21 | 0 |
| mockito | 21 | 21 | 0 |
| spring-boot-realworld-example-app | 21 | 21 | 0 |

Among them: a method of a nested class (`MockMethodAdvice#SelfCallInfo#checkSelfCall()`), a
builder generated by the DGS code generator (`Profile#Builder#image()`), a field declared in a
base class (`this.firstName = …` on `Person#firstName`), and an interface method through a
`Map` (`java/util/Map#get()`).

A mechanical check covers every global answer: the symbol's last name equals the name written
at the site (a constructor counts as its class's name, and `this(…)` and `super(…)` must name a
constructor). No global answer fails it (`java.json`, `name differs`: 0 in every project).

Three things the sample does not check: overload choice beyond the name (the symbol's
disambiguator, such as `(+1)`, was not compared with the argument types), the 5 sites where a
Lombok-generated getter puts a second symbol on the call's position (see the report), and
answers in test code, which part J leaves out.
